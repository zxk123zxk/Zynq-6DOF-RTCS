## 二、可移植性评估（分级结论）

评级：**A = 可直接移植/改少量即可用**；**B = 参考流程或改成你的接口**；**C = 不可用（技术栈冲突/超预算）**

### 2.1 A 级 —— 可直接移植（这是小五包里唯一真正值钱的部分）

| 文件 | 用途 | 移植方式 |
| --- | --- | --- |
| `graspness_/real/calibrate.py` | **眼在手外（eye-to-hand）手眼标定**：棋盘格 → 相机系 3D 点 → SVD 求刚体变换 `get_rigid_transform` → Nelder-Mead 优化 depth scale → 存 `camera_pose.txt` / `camera_depth_scale.txt` | 把 `robot.move_j_p(...)` 换成你的"示教到位"动作（或直接手推标定板），其余数学**一行不用改** |
| `graspness_/real/realsenseD415.py` / `realsenseD435.py` | RealSense 相机封装（取 RGB-D、内参） | 若你用手眼装 RealSense，改 pyrealsense2 版本即可；换其他相机则照此结构改 |
| `graspness_/utils/data_utils.py` | `CameraInfo`、`create_point_cloud_from_depth_image`、`get_workspace_mask` —— **相机内参→点云的标准实现** | 直接抄函数 |
| `graspness_/utils/collision_detector.py` | `ModelFreeCollisionDetector` 无模型碰撞检测（voxel + 抓取接近方向） | 决赛前若做"抓取位姿是否撞桌面/挡板"可参考 |
| `graspness_/real/robotiq_gripper.py` | Robotiq Modbus 夹爪驱动（连接/激活/`move_and_wait_for_pos`/位置反馈） | 若你的夹爪也是总线舵机/Modbus，这套**状态机结构**直接照抄 |

### 2.2 B 级 —— 参考流程或坐标变换，改写后可用

| 内容 | 可借鉴什么 | 不能直接用的原因 |
| --- | --- | --- |
| `graspness_/grasp_real.py` | **完整流水线骨架**：采图 → 点云 → 网络推理 → 碰撞剔除 → NMS/排序 → 工作空间过滤 → 相机系→机器人系变换 `cam2robot × grasp2camera` → `grasp_ros()` 执行 | 依赖 GraspNet 网络与 UR 接口，只保留"骨架与坐标系变换段落" |
| `graspness_/UR_Robot.py` | ① `R2rpy` / `rpy2R` / `R2rotating_vector` 旋转表示转换；② 抓取动作序列（home → 预抓取位 → 直线接近 → 闭合 → 抬升 → 放置 → 回到 home）的**状态设计**；③ 工作空间限幅、RPY 归一化到 [-π,π] | 它是 **UR 专用 socket:30003**，你没有 UR 也不该用；只能抄数学和动作序列 |
| `kr260_robotic_arm-main/opencv_ros2/` | **颜色识别→抓取→分拣的完整闭环思路**；`cv_bridge` 在 Zynq Linux 上的用法；`webcam_pub/sub` 的相机-节点结构 | 你无 ROS 环境（PetaLinux 精简 rootfs），需把 ROS 节点改写成独立进程 |
| `catkin_UR5/.../urdf/*.xacro`、MoveIt `joint_limits.yaml`/`kinematics.yaml` | **理解 6DOF 关节/连杆/限位建模**，为你的 FK/IK 或示教表提供坐标系定义参考 | ROS1 + MoveIt 无法装进你的 rootfs |

### 2.3 C 级 —— 明确不要用

- **GraspNet / Graspness 网络本体**（`models/`、`pointnet2/`、`knn/`、184 MB 权重）：需要 **MinkowskiEngine + CUDA + GPU**，且要完整 GraspNet 数据集。**你的 Zynq ARM 上跑不了，39 天也训不出来。**
- `ws_moveit`、`ur_ws`、`catkin_UR5` 的 ROS/MoveIt/Gazebo 运行时：技术栈与你的 UIO + 裸机 RTL 通路完全冲突。
- `UR_Robot.py` 的 socket 控制：UR 私有协议，与你直连舵机总线无关。

### 2.4 一句话结论

> 小五包的真正价值集中在 `graspness_/real/` 与 `graspness_/utils/`（**手眼标定 + 相机封装 + 点云 + 碰撞检测**），这些是**与机械臂品牌无关的通用视觉件**，可以为你省下 3~5 天。
> 但它的**深度学习抓取路线不适合你的赛道**。竞赛型抓取应当走"**经典视觉 + 几何/示教位姿**"，而不是 GraspNet。

### 3.2 关键风险（Top 5）

1. **夹爪没确认** —— 没有夹爪就没有"抓取"。这是比 ID 5 更该优先的事：它可能是第 6 轴，也可能是独立舵机/电磁阀。**第一周必须落实。**
2. **ID 5 的真实行程仍是空白**（0–4000 是标注值，非实测）。G3 校验会照它放行，等于没有保护。
3. **无视觉/无标定** —— 11.04 的视频若必须"视觉抓取"，则 3 周内要完成"相机接入→内参→手眼→检测→坐标变换"，风险偏高。**必须准备"固定工位盲抓"兜底视频。**
4. **无运动学** —— 6DOF 通用 IK 是数周工作量。改用**示教位姿表（teach-by-demonstration）**可规避：比赛场景固定，直接记录各工位的六个实测 count。
5. **舵机速度** —— HX-30HM 总线舵机节拍偏慢。"真·跟随"几乎不可行，动态抓取应做**"预测 + 定点拦截"**（算出物体到达抓取点的时间，提前摆好位姿等它）。

### 3.3 可行性结论

| 目标 | 判断 | 依据 |
| --- | --- | --- |
| **11.04 静态抓取文档 + 视频** | ✅ **可行（约 75%）** | 只要 W1 解决镜像/ID 5/夹爪，W2 单循环抓放，W3 补视觉或直接盲抓录制；**有兜底方案** |
| **11.20 决赛动态抓取** | ⚠️ **可行但紧张（约 50%）** | 依赖 W4–W5 的传送带 + 预测拦截按时打通；必须砍掉一切非必要项 |

### 3.4 对"安全门禁 / 风控规范"的评估（关键）

你的感受是对的，但要分清**哪些是真红线、哪些是实验级流程被错误地套到了竞赛轨道上**：

**必须保留（真红线，删了会烧舵机/伤人）：**
- 舵机独立供电 + 共地，不从 Zynq 取电；
- 上电默认物理禁发（跳线后才允许 TX）；
- PL 侧限位 / 速度 / 截止时间 / 总线互斥（编译期常量）校验；
- 独立硬件急停（不走 Linux/PS/PL 软件路径）。

**应降级或移出竞赛轨道（实验级证据要求，严重拖慢进度）：**
- 每一步运动都要"操作者逐条确认 + 证据引用归档"——竞赛期改为**一次授权、连续执行**，失败即停；
- 离线 JSON 合同（`g3_station_plan.template.json` / `g3_observation_log`）要求逐条填写证据引用，否则 `G3_PLAN_REJECTED`——**赛前可跳过**；
- "位置反馈不能单独证明抓取成功"这类哲学级判定——竞赛只需"夹爪反馈 + 视频可见"即可；
- 100 次静态循环全量记录、P99 抖动统计——**决赛后再补**，不是 11.04 的前置条件。

**一个已经付出代价的实证：** 项目历史上最严重的一次拖慢，恰恰**不是**门禁防住了风险，而是门禁自己制造的——ABI 0D 的"发前 READ 门禁"把舵机一个**瞬时**的 ERROR 位放大成**持续性全局锁死**，导致"越试越坏"，把一次本可 5 分钟定位的窄窗口问题拖成多日排查。这说明：**门禁要放在"防止不可逆动作"上（红线），而不是放在"要求每次都留证据"上（流程）。**

### 3.5 建议：双轨制

| 轨道 | 目的 | 门禁强度 | 产物 |
| --- | --- | --- | --- |
| **竞赛轨（快）** | 每周产出可演示的增量 | 红线保留，流程门禁全部关闭 | 可跑代码 + 演示视频 |
| **归档轨（慢）** | 满足文档/答辩/复盘 | 全部门禁 | 原始日志、证据表、历史快照 |

**规则：任何流程性门禁，不得阻塞竞赛轨的运动路径。**

## 五、项目推进流程与思路

### 5.1 每周节奏（固定下来，减少"看不清进度"的焦虑）

```
周一  定本周验收物 + 冻结接口           （30 min 站会）
周二~四 开发 + 每日 15 min 同步阻塞点
周五  "可演示"验收：必须跑一遍现有全链路并录屏
周六  记录归档 + 补文档（归档轨）
周日  休息 / 处理意外
```

**每周必须有一个"能跑起来给人看"的东西**——不是"完成了 80% 的代码"，而是一条能演示的链路。这样才能在 11.04 之前就发现真实的坑。

### 5.2 技术路线选择（降级原则：能跑通 > 先进）

| 决策点 | 推荐 | 理由 |
| --- | --- | --- |
| 抓取检测 | **经典 CV（颜色/轮廓/ArUco）+ 几何位姿** | GraspNet 需 GPU + 数据集，39 天不现实 |
| 目标定位 | 平面（桌面）假设：单目/深度取 x,y + 轮廓主轴取 yaw | 比赛桌面固定，2.5D 足够 |
| 逆运动学 | **示教位姿表 + 最近邻/插值**，不做解析 IK | 6DOF 通用 IK 数周工作量；工位固定 |
| 动态抓取 | **预测拦截**（算好到达时刻提前摆位姿） | HX-30HM 节拍慢，真跟随不可行 |
| 架构 | PS 侧状态机（软实时）+ PL 侧限位/时序（硬保证） | 沿用你已有的 UIO/寄存器通路，不引入 ROS |
| 传送带 | 先"停止-抓取-放行"（stop-and-go），再进"预测拦截" | 分级降险 |

### 5.3 接口冻结与回滚

- **W1 结束冻结**：PL 寄存器映射、CLI 命令集、config 限位格式。之后**只增不改**，避免反复重建镜像。
- **每周留一个可用版本**（git tag / 镜像归档），万一本周翻车可回退。
- 镜像构建与源码必须同步（`BOOT.BIN` 变了要重跑 SD 打包）。
