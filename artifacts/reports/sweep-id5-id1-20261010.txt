RTCS ID 5 / ID 1 逐字节扫描对照（2026-10-10，BusLinker USB，严格只读）
源数据：操作者板端 `rtcs-buslinker-g1 --device /dev/ttyACM0 --id 5|1 sweep`

== 1) 全 72 地址逐字节差异 ==
ID5 与 ID1 仅 7 个地址不同：

 addr    ID5   ID1   性质
 0x05    05    01    舵机 ID（本就应不同）
 0x09    86    E9    ★ 文档空档 0x08..0x0D 之内
 0x0B    01    FB    ★ 文档空档 0x08..0x0D 之内
 0x38    01    95    当前位置低字节（读数随姿态变化）
 0x3F    34    30    当前温度 52C / 48C
 0x43    01    95    与 0x38 读值相同，属扫描伪影（见第 3 节）
 0x45    0F    00    当前电流 15mA / 0mA

其余 65 个地址逐字节相同。

== 2) 关键：0x09 与 0x0B 恰好落在 V3.7 寄存器表跳过的空档里 ==
V3.7 表从 0x08 直接跳到 0x0D。Feetech 系固件（本表头固件 SMServo2.40-STM32-485）
在此处放两个 16 位字段：0x09 最小角度限制、0x0B 最大角度限制。
实测该处可读、servo_error=0x00，说明寄存器存在。

扫描只取到每个 16 位字段的低字节（高字节见第 3 节的伪影），但配合"哪些目标被接受"
即可唯一反解：

ID 5：低字节 0x86（min）、0x01（max）
  约束 a：目标 2000 被接受        -> min <= 2000 <= max
  约束 b：目标 1900 被拒绝        -> 1900 < min
  约束 c：目标 2100 / 2200 被拒绝 -> max < 2100
  min 低字节 0x86 的候选 {0x0786=1926, 0x0886=2182, 0x0686=1670 ...}
    仅 1926 同时满足 b 与 a      -> min = 1926
  max 低字节 0x01 的候选 {0x0001=1, 0x0101=257, ..., 0x0801=2049, 0x0901=2305 ...}
    仅 2049 同时满足 c 与 a      -> max = 2049
  => ID 5 允许窗口 = [1926, 2049]

  与全部实地记录逐条吻合：
    目标 2000 被接受（起点 2322 / 2059 / 1932 三次都成功，位移最大 322 步）
    目标 1900 / 1800 / 1700 / 1600 / 2100 / 2200 / 2500 / 3000 / 1500 / 1000 全部被拒
    被拒时刻 elapsed_ms=5、状态包 ERROR=bit4（角度），舵机尚未启动

ID 1：低字节 0xE9（min）、0xFB（max）
  min = 0x03E9 = 1001（config/g2_measured_limits.toml 实测 safe_min = 1000，吻合）
  max = 0x0BFB = 3067（该轴实测 safe_max = 3000，且 ABI 08 日志中 ID1 从 2989 走到 2010
       成功，证明 2989 在允许窗口内，故 max >= 2989 —— 与 3067 相容）
  => ID 1 允许窗口 = [1001, 3067]，与操作者实测的 [1000, 3000] 基本一致

=> 结论：ID 5 与 ID 1 的差别不在我们读过的任何寄存器，而在 0x09 / 0x0B 这一对
   角度限制。ID 5 的这一对被改成了围绕 2000 的极窄窗口，所以它拒绝一切远离 2000
   的目标；ID 1 的这一对是正常的大范围，所以它能走 1000..3000。

== 3) 扫描工具自身的已知伪影（必读，避免误读）==
本轮的 `sweep` 每地址只读 1 字节，实测该舵机对"单字节读取"的应答不总是可信：
以下 14 个地址（全部是某个 16 位字段的高字节位置）返回固定 0xD0，
而同地址在多字节读取中返回正确值（例：dump 读 0x10 长度 2 -> [E8 03]，
单字节读 0x11 -> D0）：

  0x0A 0x0C 0x11 0x19 0x20 0x2B 0x2D 0x2F 0x31 0x39 0x3B 0x3D 0x44 0x46

另有一处地址别名伪影：单字节读 0x43 与单字节读 0x38 返回同一个值（ID5 都是 01，
ID1 都是 95），而 0x38 的多字节读取给出真实位置（ID1 曾为 [CF 07 00 00]）。

因此：
  * 0x09 / 0x0B 的低字节可信（它们是字段首字节，不在伪影地址表中）；
  * 上述 14 个地址的 0xD0 不是数据，不得写入任何诊断结论；
  * 16 位字段一律用多字节读取（`dump` 读 0x09 长度 4）确认，不要用单字节扫描。

== 4) 待确认（一条命令即可）==
当前板上镜像的 `dump` 已含 4 字节读取 `gap_09_0c`：

  sudo rtcs-buslinker-g1 --device /dev/ttyACM0 --id 5 dump

预期出现形如 `reg name=gap_09_0c addr=0x09 len=4 raw=[86 07 01 08] servo_error=0x00`
（即 min=0x0786=1926、max=0x0801=2049）。若如此，窗口假设即被独立证实。
