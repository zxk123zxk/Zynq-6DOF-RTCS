# G2：六轴实测限位与同步运动

**阶段状态：已结束（2026-10-09，依据操作者确认）。** 操作者报告 ABI 12 六轴联动顺利执行，硬件部分无风险。本仓库尚未收到该次运行的完整终端日志，也未收到重复同步写、越限拒绝、软件停止延迟及独立断电急停的逐项原始记录；不把这些未提交的记录写成已核验数据。后续如补交日志，可直接追加到本节的实物证据中。G3 的 100 次静态抓放是新阶段验收。

## 已交付的 G2 能力

- 六个唯一 ID 的安装状态实测闭区间与原始速度上限 1500 编入实际 TTL 顶层；PL 发前复核目标、参数、物理禁发、截止时间和总线占用。推荐原始速度 500；原始时间/速度字段不推定物理单位。
- 单轴与六轴均现场 READ 起点；六轴使用一帧 SYNC WRITE，广播没有协议 ACK。单播 ACK、WRITE 已启动、位置变化及进入误差带分别报告。默认逐轴容差 ±30 count、观察期 5 秒，可在规定范围内显式调整；成功要求连续三轮反馈到位。
- 命令故障仅属于本次提交。故障后不会自动重试；总线空闲后，由操作者再次显式提交。软件 stop 现场 READ 六轴后广播保持，独立断电急停仍是单独的硬件路径。
- 原先叫作 home 的六个数现称测得的参考位置。ID 2/6 位于限位下端、ID 3/4 位于上端，不构成安全回位姿态；没有自动回位命令。

## 核心验收命令

完整板端顺序、接线、预期输出、停止条件与 SD 哈希以 [当前 SD 操作说明](SD启动与项目迭代操作说明.md)为准。离线回归命令：

    bash sim/run_regression_wsl.sh

板端先在物理禁发状态核对版本和实测限位，允许发送后再清点实时位置：

    sudo rtcs-pl-g1 --uio /dev/uio0 probe
    sudo rtcs-pl-g2-six --uio /dev/uio0 limits
    sudo rtcs-pl-g2-six --uio /dev/uio0 inventory

六轴目标必须由操作者依据本次 inventory 明确填写，不能照抄参考位置。同步写、重复同步写、越限拒绝、软件 stop 和独立断电急停的原始输出是实物验收的可复查材料。
