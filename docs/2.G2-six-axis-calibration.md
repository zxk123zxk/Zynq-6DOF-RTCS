## 已交付的 G2 能力

- 六个唯一 ID 的命令闭区间与原始速度上限 1500 编入实际 TTL 顶层；ID 5 的 0–4000 为操作者认可的命令范围，不代表机械全行程实测。PL 发前复核目标、参数、物理禁发、截止时间和总线占用。推荐原始速度 500；原始时间/速度字段不推定物理单位。
- ABI 0D 的单轴与六轴均现场 READ 起点。当前源码 ABI 0E 的显式绝对目标不再预读起点；单轴仍要求正常 WRITE ACK 和发后连续三轮有效到位反馈，六轴 SYNC WRITE 仍要求六轴连续三轮有效到位反馈，广播没有协议 ACK。未采集的起点/实际位移标为 `UNAVAILABLE`，不能推断运动已发生。
- 命令故障仅属于本次提交。故障后不会自动重试；总线空闲后，由操作者再次显式提交。软件 stop 现场 READ 六轴后广播保持，独立断电急停仍是单独的硬件路径。
- 原先叫作 home 的六个数现称测得的参考位置。ID 2/6 位于限位下端、ID 3/4 位于上端，不构成安全回位姿态；没有自动回位命令。

## 2026-10-10 故障诊断增量（仅离线验证）

本节最初的诊断增量以 ABI `0x5254000D` 开发；当前源码与仓库 SD 镜像均为 `0x5254000E`，板端旧输出仍须按旧 ABI 解读。单轴在 G2 DONE 时立即读取 G1_FAULT/G1_RESULT，并记录 phase、engine_fault、servo_error_raw、逐位含义、起点/目标/末次有效反馈、有效位、WRITE/单播 ACK、主机完成时 `epoch_ms` 和相对 `elapsed_ms`。`incident_position` 只在校验有效的 READ 错误时有意义，WRITE 应答不包含位置。六轴使用 DIAG 锁存原故障；原始故障为广播发后 READ 失败时，CLI 对还没有 PL 反馈的其他轴各做至多一次有界 READ，标为 `post_fault_read_only`，其结果不改变原命令失败状态，也不产生第二帧运动命令。`snapshot_epoch_ms` 是主机取结果快照的时间，不伪称为每次 PL READ 的物理发生时间；后补 READ 各有独立时间戳。

HX-30HM 仓库内[寄存器表](resource_file/HX-30HM寄存器列表及参数.xls)的 0x41 状态位：bit0 电压、bit1 传感器、bit2 温度、bit3 电流、bit4 角度、bit5 过载；bit6/7 未定义，按原始位保留。通信[协议](resource_file/幻尔HX-30HM总线舵机通信协议文档.pdf)规定状态包含 ERROR。`engine_fault=8` 表示状态包校验有效且 ERROR 非零；`servo_error_raw=0x10` 只确定舵机报告**角度类状态**。其余引擎故障不可推断 ERROR 字节，输出 `UNAVAILABLE`。PL 发前越限 `fault=12`、`write_sent=0` 可确定为 PL 限位拒绝；CLI 自己的越限拒绝同样没有发帧。

## ABI 0x5254000E：显式绝对目标直接 WRITE（离线构建通过，待板端验收）

操作者报告 ABI 0D 下 ID 5 手动移至约 3000 后，显式 `--target 2000` 因发前位置 READ 失败得到 `start=UNAVAILABLE fault=5 write_sent=0`。这表示**目标尚未发送**，不能用该日志判断舵机拒绝了 2000。ABI 0E 删除单轴 `move` 与六轴 `move-six` 的发前 READ 阶段，二者在 PL 完成目标、原始速度、物理禁发、截止时间和总线占用检查后直接发各自唯一的运动 WRITE。相对 `calibrate-step` 必须读起点才能计算目标，`stop` 必须读当前位置才能广播保持，仍保留功能性发前 READ。

绝对命令不采起点，`start=UNAVAILABLE`、`start_valid=0`、`actual_delta=UNAVAILABLE`；六轴 `start_valid_mask=0x00`、`position_change_mask=UNAVAILABLE`，均不得写成位置未变化或已变化。发后有效位置仍报告 `last`、`target_error`、`in_band`。单轴只有正常 WRITE ACK、有效发后 READ 与 PL 连续三次到位时才成功；六轴广播没有 ACK，只有六轴各自有效反馈并完成连续三轮全轴到位才成功。舵机 ERROR 继续按发生阶段及原始字节报错；无自动重试，也不把故障改成 OK。发后 READ 失败的绝对命令现在会显示 `write_sent=1`、`phase=post_write_feedback` 或 `post_write_read`，而不会因发前 READ 故障在 `write_sent=0` 停止。位置反馈不能单独证明曾经位移或抓取成功。

起点有效位和成功判定语义已改变，因此源码版本从 0D 升为 0E；寄存器地址未移动。单轴绝对命令已无基于起点位移的 fault 16，观察期内未能连续到位仍报 fault 9。2026-10-12 已重建匹配的 bitstream、XSA 与 SD 三件套并通过离线回归和时序门禁，旧文件见[归档](../artifacts/archive/g2-id5-angle-window-20261012/README.md)。

## 2026-10-12 板端验收：ABI 0E 上板且 ID 5 远端运动成功

操作者已刷入 ABI `0x5254000E`（`physical_tx=ENABLED`），并以单轴远端目标实测 ID 5：

    sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 1500 --speed-raw 500 --time-raw 100 --execute

关键读数：20 个样本，位置由 1907 单调推进至 1510（`target_error=10`），`in_band=1`、`write_sent=1`、`unicast_ack=1`、`fault=0`、`fault_id=5`，`elapsed_ms=1008`、`timing=WITHIN_2S`，全过程 `servo_error_raw=0x00`。起点/实际位移为 `UNAVAILABLE`（ABI 0E 不采起点）。

**结论：** 旧的 [1926, 2049] 舵机内部角度窗口已由官方软件重新校准解除，ID 5 现在能接受远离 2000 的目标。这同时验证了 ABI 0E 在板端确实运行、且"删除发前 READ 门槛"后绝对命令可以正常发出并到位。**ID 5 的 0–4000 仍是命令范围标注，不是机械全程实测**；G3 首次工位标定时应补记其真实可用区间。

**扫描伪影。** 早期逐字节 `sweep` 在 0x0A、0x0C、0x11、0x19、0x20、0x2B、0x2D、0x2F、0x31、0x39、0x3B、0x3D、0x44、0x46 等 16 位字段高字节位置可返回固定 `0xD0`；单字节 0x43 还与 0x38 别名。现用偶地址双字节读；16 位字段以多字节 `dump` 为准，不把伪影当真实配置。完整清单见扫描分析。

**与 ABI 的关系。** ABI 0D 的绝对命令发前 READ 失败可得 `fault=5 write_sent=0`，表示根本没发 WRITE；舵机拒绝旧窗口外目标则是 `write_sent=1 phase=write_ack engine_fault=8 servo_error_raw=0x10`。ABI 0E 删除前一门槛，但不会修复舵机 NVS。两类日志不能合并为一次故障。

### 写回通路（保留能力，本次不重复执行）

`rtcs-buslinker-g1 write-reg` 仅允许单播写 0x09、0x0B、0x37，要求 `--confirm-write`，每次写前和写后各读回一次；读动词仍只读，失败不自动重试。守护脚本验证白名单外地址、缺确认和广播 ID 一帧不发。此前的可回退试探方案是先令 0x37=1 再写角度窗口；0x37=1 时 NVS 改动掉电不保存。操作者现已用官方软件完成重新校准，仓库无该次写回原始输出，因此不再照旧方案重复写寄存器，也不宣称新窗口已被日志验证。

### 六轴 CLI 变更：删除 `inventory`

`inventory` 与 `diagnose` 是同一段"逐轴 READ_POSITION"循环，而 `diagnose` 是它的严格超集
（额外打印原始 `servo_error`、逐位含义、`read_fault` 与原因，并在异常时返回非零）。
保留两个入口只会让人误用信息更少的那个，故删除 `inventory`；`diagnose` 保留。
现存文档、离线脚本与该守护测试已同步更新。`limits` / `diagnose` / `torque-status` 是
[G3 验收清单](3.G3-static-closed-loop.md)明确要求的三条只读命令，予以保留。
