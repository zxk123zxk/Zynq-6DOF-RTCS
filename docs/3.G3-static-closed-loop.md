# G3：固定工位静态抓放闭环

**状态：前期准备。** G2 已由操作者于 2026-10-09 确认结束。G3 面向固定工位的可重复抓放，不包含视觉目标预测或传送带追踪；100 次静态循环属于 G3 验收，尚未进行。

## 实施前需要固定的实测输入

| 输入 | 用途与当前状态 |
| --- | --- |
| 六轴安全待机、接近、抓取、抬升、放置、退出目标 | 须逐点实测为六个原始 count，并验证每段路径和负载空间；当前未提供。G2 的参考位置有轴位于限位端点，不能代替待机姿态。 |
| 夹爪实际 ID、开/闭原始目标及安全范围 | 须确认它是否占用六个舵机之一；当前未提供，不假定 ID 6 是夹爪。 |
| 关节方向、工具与负载、抓放高度、障碍物边界 | 用于轨迹方向、碰撞边界与静态工位设计；不从 count/角度近似关系推断。 |
| 速度/时间原始字段对应的实测延迟和终点误差 | 用于选择各步骤容差、观察期及后续轨迹参数；当前 ABI 12 的默认值仅是反馈验收策略。 |

## 分阶段实现

1. **只读记录与离线任务表。** 先保存每个静态工位点的六轴实时位置、负载状态、机械空间照片/尺寸和时间戳。任务表只包含操作者确认的显式六轴目标；在离线模式检查六个唯一 ID、实测限位和原始速度上限，不发 WRITE。
2. **单循环人工监督。** 以现有 ABI 12 六轴命令逐段执行接近、抓取、抬升、放置和退出。每步保存六轴 start/target/last、实际位移、目标误差、fault、WRITE 状态、耗时；下一步仅在本步确认后由操作者显式启动。失败时停止序列，不自动重试或返回限位端点。
3. **受控自动状态机。** 经单循环实测后再设计 PS 侧任务状态机、PL 命令 FIFO/截止时间/IRQ、同步轨迹和看门狗。新路径必须沿用 G2 的 PL 限位、物理禁发、总线互斥、逐轴反馈与独立急停约束；保留 ABI 12 手动命令作为诊断入口。寄存器语义改变时升级 ABI，并分别构建匹配镜像。
4. **100 次静态循环。** 在固定工位、固定负载和明确起点下记录每次成功/失败、六轴最大目标误差、抓取结果、人工干预、步骤延迟与抖动。任一故障结束当前循环并记录恢复动作，不将失败循环计作成功。

当前 [trajectory_engine.sv](../src/pl/rtl/trajectory_engine.sv)只是空接口，IRQ 也尚未接入 G3 状态；不能把它们写成已实现能力。先取得上述实测输入，再决定梯形轨迹和 FIFO 的深度、插补周期与超时阈值。

## 核心目录与第一项可执行工作

- [config/](../config/g2_measured_limits.toml)：保留 G2 实测限位；新增 G3 工位点时只录实测数据，不生成“安全默认姿态”。
- [src/ps/linux/apps/](../src/ps/linux/apps/rtcs_pl_g2_six.c)：先增加独立的只读记录/离线检查工具，再做静态任务状态机。
- [src/pl/rtl/](../src/pl/rtl/trajectory_engine.sv)：待时序数据确定后实现 FIFO、轨迹、超时、看门狗和 IRQ；不绕过当前 G2 控制路径。
- [sim/](../sim/README.md)：逐步覆盖非法任务表、越限、超时、反馈故障、stop 与急停优先级。

G3 的第一个可审查产物应是**六轴工位点实测表和单循环逐步日志**。在它们到齐前，不编造抓放目标，也不开放无人监督的自动循环。
