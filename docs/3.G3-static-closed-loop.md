# G3：固定工位静态抓放闭环

**状态：进行中。** RTL/CLI 能力已齐备（ABI `0x5254000E` 已上板并实测）；**ID 5 窄窗口已由官方软件重新校准并实测通过**（[G2 根因](2.G2-six-axis-calibration.md)）；**夹爪执行器已确认为 ID 6 舵机**。本阶段剩下的工作是实测工位点、打通六步单循环、再做连续自动循环。

**门禁约定：本阶段按[双轨制](0.1hardware_bringup.md)执行——竞赛轨只保留红线门禁，流程门禁（逐条操作者确认、离线任务表证据引用、100 次全量记录）归入归档轨，不得阻塞运动路径。**

## G3 的机械与执行器基线

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 关节 | ID 1–5 | 用户 2026-10-12 确认 |
| 夹爪 | **ID 6 舵机**（开/合各一个原始 count 目标） | 用户 2026-10-12 确认；[任务表](../config/g3_station_plan.template.json) 的 `gripper_servo_id` 应填 `6`，不再是 null |
| 自由度 | 5 关节 + 夹爪 | 末端位置（ID 1–3）+ 手腕俯仰（ID 4）+ 偏航（ID 5） |
| 板端 ABI | `0x5254000E`，`physical_tx=ENABLED` | 2026-10-12 板端实测 |
| 限位来源 | [config/g2_measured_limits.toml](../config/g2_measured_limits.toml) | ID 1–4/6 为实操实测；ID 5 的 0–4000 是命令范围标注，本阶段应补记真实可用区间 |
| 夹爪方向 | 待实测：需确认 ID 6 的"开"与"合"对应 count 的大小方向 | 不得猜测 |

> **注意**：ID 6 既是六轴广播命令的第 6 个轴，也是夹爪。因此"六轴同步 move"会把夹爪目标一起下发——这是期望行为（例如待机/接近步 ID 6 保持开，抓取步 ID 6 给合的目标值）。**不要为夹爪另建一条旁路**，沿用现有六轴命令即可。

## 现在可执行的只读工作（每次都做，几分钟）

机械臂静止、物理允许跳线使总线 READ 可用时，保存完整只读输出：

    sudo rtcs-pl-g2-six --uio /dev/uio0 limits
    sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose

`diagnose` 逐轴发送 READ_POSITION，不带 `--execute`、不发 WRITE；末行应为 `OK issues=0 read_only=1 write_sent=0`。任一 ID 的 `read_fault` 或 ERROR 非零时，存输出后再排查，不自动重发目标。

## 实施步骤（竞赛轨，已按双轨制精简）

### 步骤 1：确认夹爪角色与方向（半天）

- 用 `sudo rtcs-pl-g2 --uio /dev/uio0 move --id 6 --target <A> --speed-raw 500 --time-raw 100 --execute` 分别尝试两个候选目标，**目视确认**开/合方向，记录"开"与"合"的原始 count。
- 同时记录 ID 6 的可达范围（若无物品夹持时可走到的两端）。
- 产出：`config/` 中记录夹爪开/合 count 与该轴真实区间。

### 步骤 2：实测六个工位点（半天）

对 `standby / approach / grasp / lift / place / exit` 六步，用示教方式（手动把机械臂摆到目标姿态 → `diagnose` 读六个位置）记录**六个原始 count**。

- 建议工位布局：物体放在传送带中段固定位置的平面工装内；place 位为侧边料盒。
- **grasp 步必须实测"夹爪闭合后物体被稳定夹持"**，不能只看位置反馈。
- 产出：六步 × 六轴的实测目标表（可先写在 `docs/` 或 `config/` 的实测说明里，不必先填满离线任务表 JSON）。

### 步骤 3：单循环六步（1 天）

按 `standby → approach → grasp → lift → place → exit` 逐步下发 `move-six`，每步之间由操作者确认工件与路径状态。

     sudo rtcs-pl-g2-six --uio /dev/uio0 move-six \
       --axis 1:<目标1>:500:10 --axis 2:<目标2>:500:10 \
       --axis 3:<目标3>:500:10 --axis 4:<目标4>:500:10 \
       --axis 5:<目标5>:500:10 --axis 6:<目标6>:500:10 \
       --observe-ms 5000 --execute

保存每步的 `target/last/target_error/fault`；任一步 ERR 或机械异常即停止当次循环，**不自动重试**。

### 步骤 4：连续自动循环（2–3 天）

- PS 侧写一个**任务状态机**：按顺序下发六步，每步读取 `fault` 与到位结果；成功则进下一步，失败则停在当前步并保留日志。
- **竞赛轨口径**：一次授权后连续跑 N 次（建议先 N=10 验证稳定性），失败即停，不要求每步人工确认。
- 记录：每次循环的成功/失败、六轴最大目标误差、人工干预次数、单次循环耗时。
- 产出：连续 10 次成功的原始日志 + 一段视频。这就是 **11.04 的兜底交付物**。

### 步骤 5（归档轨，周末补）：证据与文档

- 把步骤 1–4 的原始输出、工位实测表、夹爪方向证据整理进证据目录。
- 需要完整可复查性时，再按 [离线任务表](../config/g3_station_plan.template.json) 与 `scripts/g3_offline_plan.py` 补填 `operator_confirmed` 与证据引用；该检查**不参与竞赛轨的放行**。

## 停止条件

任一 ERROR、失 ACK、反馈无效、位置停滞、机械干涉、供电异常或动作超出预期，立即停止后续运动提交，必要时独立断电急停；**不自动重试、不放宽容差、不把静止正常记录为运动通过**。
