# G3：固定工位静态抓放闭环

**状态：进行中。** ABI `0x5254000E` 的 RTL/CLI 已上板，ID 5 窄窗口已解除（见 [G2](2.G2-six-axis-calibration.md)）。夹爪为 ID 6；2026-10-13 重新校准后，张开目标 2500 的单轴运动成功。操作者报告 2100 命令使夹爪在约 2373 夹住小黑方块，同时舵机报 `0x20` 过载：记录为“实物夹住、G2 命令失败”两项事实。不同尺寸工件的接触 count 不同，不要求先找一个对所有物体都无过载的固定闭合点。本阶段仍需六个工位点与六步单循环。

**门禁约定：本阶段按[双轨制](0.1hardware_bringup.md)执行——竞赛轨只保留红线门禁，流程门禁（逐条操作者确认、离线任务表证据引用、100 次全量记录）归入归档轨，不得阻塞运动路径。**

| 项 | 取值 | 依据 |

| 限位来源 | [config/g2_measured_limits.toml](../config/g2_measured_limits.toml) | ID 6 新 PL 命令范围 2050–3000 已编入仓库镜像；板端仍读出 1585–2500，须更新镜像并核对。ID 5 的 0–4000 是命令范围标注 |
| 夹爪方向与接触 | 下臂静止、上臂活动；count 增大时张开。2500 张开到位；2100 夹小方块时约 2373 接触并报 `0x20`。黄方块等更小工件须分别观察实际夹持 | 方向、2050–3050 可达无干涉由操作者确认；2500/2100 结果见 [G2 新试验](2.G2-six-axis-calibration.md) |

> **注意**：ID 6 既是六轴广播命令的第 6 个轴，也是夹爪。因此"六轴同步 move"会把夹爪目标一起下发——这是期望行为（例如待机/接近步 ID 6 保持开，抓取步 ID 6 给合的目标值）。**不要为夹爪另建一条旁路**，沿用现有六轴命令即可。

## 只读诊断基线（已通过）

**2026-10-12 已完成**：`limits`（`calibrated_mask=0x3f`）与 `diagnose`（六轴 `servo_error=0x00`、`read_fault=0`、`RTCS_PL_G2_SIX_DIAG OK issues=0 read_only=1 write_sent=0`）全绿，原始输出见 [G2 板端基线](2.G2-six-axis-calibration.md)。此外 `torque-status --id 5` 读回 `0x28=0`（上电默认卸力）。

`limits` 与 `diagnose` 可在需要定位问题时随时只读复核；它们不是每条显式运动命令的前置 READ 或审批。

## 实施步骤（竞赛轨，已按双轨制精简）

### 步骤 1：记录夹爪方向与不同工件的接触结果

- 操作者确认 ID 6 重新校准后 2050–3050 两端可达且无干涉，选择 2050–3000 为新 PL 命令范围；仓库镜像已重新打包，上板后才生效。2026-10-13 板端读回仍是旧范围 1585–2500。更新前不要依据新范围发运动命令。
- 2500 张开命令发后有效位置 2486、`fault=0`；2100 夹小方块命令在 2373 停滞、`target_error=273`，约 2.2 s 后舵机报 `servo_error_raw=0x20`（过载），`fault=5`。保留原始故障，不扩大容差、不重试、不把夹住工件等同于伺服到位。
- `config/g2_measured_limits.toml` 记录 2500 为已验证的张开目标、2100 为报过载的夹取试验目标。黑方块约 2373 接触只是这次工件和姿态的观察，不能变成黄色小方块或其他物体的通用闭合 count。
- G2 继续如实输出当次 `fault` 和 `servo_error_raw`；下一条**显式**命令不因前次错误而被锁死。G3 将“伺服到位”“实物夹住”“舵机过载”分开记录；操作者可依据现场夹持状态选择下一步，不把 `0x20` 改写为 `fault=0`。未来自动任务应有明确的接触事件处理策略，而不是要求每个工件事先找到一个无过载 count。
- [现场照片](../artifacts/reports/g3-20261013-board-arm-black-cube.jpg)显示已打印棋盘格、机械臂和一个黑色方块；照片不能证明三件同规格工件已制作，也不能证明 USB 相机角点检测已通过。**棋盘格路线已于 2026-10-14 作废**（角点检出不稳、误检严重；抓取背景固定为黄色桌面 / 绿色传送带，见 [G4](4.G4-static-vision-grasp.md)），该照片仅作为当日现场记录保留。

### 步骤 2：实测六个工位点（半天）

对 `standby / approach / grasp / lift / place / exit` 六步，用示教方式（手动把机械臂摆到目标姿态 → `diagnose` 读六个位置）记录**六个原始 count**。

- 建议工位布局：物体放在传送带中段固定位置的平面工装内；place 位为侧边料盒。
- **grasp 步必须实测"夹爪闭合后物体被稳定夹持"**，不能只看位置反馈。
- 产出：六步 × 六轴的实测目标表（可先写在 `docs/` 或 `config/` 的实测说明里，不必先填满离线任务表 JSON）。

### 步骤 3：单循环六步（1 天）

按 `standby → approach → grasp → lift → place → exit` 逐步下发 `move-six`，每步之间由操作者确认工件与路径状态。

     sudo rtcs-pl-g2-six --uio /dev/uio0 move-six \
       --axis 1:<目标1>:500:10 --axis 2:<目标2>:500:10 \
       --axis 3:<目标3>:500:10 --axis 4:<目标4>:500:10 \
       --axis 5:<目标5>:500:10 --axis 6:<目标6>:500:10 \
       --observe-ms 5000 --execute

保存每步的 `target/last/target_error/fault` 和实物夹持结果。ERR 只判定**当次命令**失败；操作者结合现场状态决定下一条显式命令，软件不因历史故障锁死，也不自动重发失败命令。出现实际机械干涉或失控动作时使用独立断电急停。

### 步骤 4：连续自动循环（2–3 天）

- PS 侧写一个**任务状态机**：按顺序下发六步，每步分别记录 G2 命令结果与实物任务结果。故障事件保留原值，由该步的任务策略决定继续、改下一个目标或结束本次循环；不设置跨命令错误锁存。
- CLI 对当次故障返回非零退出码；调度器应读取该结果并作任务决策，不能用 shell 的 `&&` 串联六条命令，让一个退出码无意中成为全流程禁动门禁。
- **竞赛轨口径**：一次授权后连续跑 N 次（建议先 N=10 验证稳定性），不要求每步人工确认；实际机械干涉仍由物理急停处理。
- 记录：每次循环的成功/失败、六轴最大目标误差、人工干预次数、单次循环耗时。
- 产出：连续 10 次成功的原始日志 + 一段视频。这就是 **11.04 的兜底交付物**。

### 步骤 5（归档轨，周末补）：证据与文档

- 把步骤 1–4 的原始输出、工位实测表、夹爪方向证据整理进证据目录。
- 需要完整可复查性时，再按 [离线任务表](../config/g3_station_plan.template.json) 与 `scripts/g3_offline_plan.py` 补填 `operator_confirmed` 与证据引用；该检查**不参与竞赛轨的放行**。

## 故障与后续命令

ERROR、失 ACK、反馈无效和位置停滞均如实记入**当次**诊断；不把它们改写为 OK，也不建立禁止后续显式命令的全局门禁。机械干涉、失控动作或供电异常由现场操作者使用独立断电急停处理。
