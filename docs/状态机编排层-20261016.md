# G3 状态机编排层 · 骨架与验收（2026-10-16）

等待相机/训练的空窗期产物：把"单循环六步"做成**参数化状态机**，一份代码同时服务
盲抓（固定示教点）和视觉抓（映射坐标）。全程不碰真舵机，离线可回归。

## 1. 新增文件与原理

| 文件 | 职责 | 原理 |
| --- | --- | --- |
| `scripts/g3_station_runner.py` | **状态机编排层（核心）** | 读已确认的 `g3_station_plan.json` → 复用 `g3_offline_plan.validate` 门禁（ID5 放行/越界/preflight/六步顺序）→ 顺序执行六步：每步 subprocess 调 `rtcs-pl-g2-six move-six`（真正的组帧/限位/总线时序在 PL）→ 解析 `RTCS_PL_G2_SIX_OK` / `ERR g2_six_fault` 判定成败 → **故障留痕不锁死**（某步失败→记故障→跳 exit 安全回位→本轮失败→下一轮继续）→ 支持 `--once` / `--loop N` / `--dry-run` / `--grasp-xy` |
| `scripts/grasp_point_map.py` | **抓取点参数化几何层** | 工作平面 `(x,y)` → 六轴 target。示教表最近邻/双线性插值（ID 1-3 随坐标变、ID 4-6 固定姿态）；`map_grasp_analytic` 精确两连杆解留 TODO 待工位几何实测 |
| `sim/run_g3_station_runner_guard.sh` | **离线回归** | mock 的 move-six（Python 脚本），测四件事：①六步顺序 ②故障不锁死（grasp 失败→exit 回位→第二轮跑通）③越界计划被拒 ④`--grasp-xy` 覆盖抓取点 |

## 2. 数据流

```
visual (u,v) ─plane_mapping.py─> (x,y)
                                    │
grasp_point_map.map_grasp(x,y,table,fixed_pose) ──> 六轴 target（覆盖 approach/grasp/lift 的 ID1-3）
                                    │
g3_station_runner.py ──> 每步 move-six ──> rtcs-pl-g2-six ──> PL（组帧/限位/总线）
      │（盲抓时跳过映射，直接用计划里的固定示教点）
      └─ 六步：standby → approach → grasp → lift → place → exit
```

## 6. 安全边界（与现有红线一致）

- 编排层**不发任何一帧**，只调 `rtcs-pl-g2-six`（帧由 PL 拼、限位由 PL 裁）；
- 越界/未放行 ID5/缺 preflight 的计划在 `validate` 阶段即被拒，不会执行任何运动；
- exit 步回位失败 → 立即终止（安全无法保证时不硬继续）；
- 单步故障如实留痕、不锁死后续轮次，但**不自动重试**同一命令。

## 7. 夹爪拆分（2026-10-19 修订，必读）

### 7.1 为什么不能把夹爪并进 move-six

`move-six` 的到位判定是**六轴连续三轮全部进容差带**（默认容差 30 count）。
夹爪夹住物块的物理结果是：舵机被物块顶住，停在接触位置（10-17 实测命令 2200 → 停 2367），
同时舵机 ERROR 报过载（`servo_error_raw=0x20`）→ PL 判 `fault=5`。
所以只要把 ID 6 的闭合目标写进 `move-six`，**每一次抓取都会被判失败**，而且这个结论与机械是否正常工作无关。

### 7.2 现在的动作拆分

一个抓取动作拆成两段，走两条不同的 CLI：

```
六轴到位（夹爪保持张开 2500）  →  rtcs-pl-g2-six move-six
        ↓
夹爪闭合（单轴，允许过载）      →  rtcs-pl-g2 move --id 6 --target 2200
        ↓ 判定 CONTACT，取回接触位置（如 2367）
后续各步 ID 6 目标 = 接触位置   （Hold，容差放宽到 100）
        ↓
夹爪张开（单轴）                →  rtcs-pl-g2 move --id 6 --target 2500 → 解除 Hold
```

判定口径（`judge_gripper`）：

| 输出 | 语义 | 是否算成功 |
| --- | --- | --- |
| `RTCS_PL_G2_OK` | 正常到位 | 是 |
| `write_sent=1` 且 `servo_error_raw` 带 `0x20` 过载位（闭合步 `expect_overload=true`） | `CONTACT` 夹住了 | 是，单独留痕 |
| 其余（含 `write_sent=0`） | 真故障 | 否 |

**注意**：过载只在"闭合"这一步被接受，且要求计划里显式写了 `expect_overload: true`；
张开步期望 `false`，张开失败（如 10-17 的 `fault=8`）仍然算失败，不会静默通过。

### 7.3 计划里的写法

`config/g3_station_plan.json` 的两步增加可选字段 `gripper`：

```json
{"name": "grasp", "target_count": [2061, 2130, 2073, 3009, 2006, 2500],
 "gripper": {"command": "close", "target_count": 2200, "expect_overload": true}}

{"name": "place", "target_count": [1164, 2433, 2030, 2723, 2013, 2500],
 "gripper": {"command": "open", "target_count": 2500, "expect_overload": false}}
```

要点：**grasp 步 `target_count` 的 ID 6 必须是"张开"值（2500）**，闭合目标只放在
`gripper.target_count`。place 步的 ID 6 同理只是名义值，执行时会被 Hold 覆盖，
到位后才张开。`gripper.target_count` 必须落在 ID 6 实测范围 2050–3000 内，门禁会拦。

### 7.4 新增命令行参数

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--single-cli` | `rtcs-pl-g2` | 夹爪单轴 move 可执行路径（回归注入 mock） |
| `--observe-ms` | `8000` | 六轴到位观察期；长杆大位移（ID2 +1241）默认 5000 不够，会 fault=9 |

### 7.5 占位步门禁（新增）

`--dry-run` 允许打印含占位步的计划（便于人工审阅指令）；
**真跑**（不带 `--dry-run`）时，任何一步 `measured_at` 以 `TODO` 开头即拒绝整份计划：

```

```

这条门禁把"用复位值占位当 approach/lift 真跑"这类事故挡在发帧之前。

## 8. 限位表与 PL 综合常量的同步校验（2026-10-19 新增）

`scripts/check_limit_sync.py`：把 `config/g2_measured_limits.toml` 与
`src/pl/rtl/g2_board_limits_pkg.sv` 的 `SAFE_MIN/SAFE_MAX/SPEED_MAX_RAW/CALIBRATED_MASK`
逐轴对比（注意 SV 打包字面量是高位在前，脚本按"读入后反转"还原成 ID 1..6）。

- 已挂进 `sim/run_regression_wsl.sh` 的**第一项**，输出 `LIMIT_SYNC_OK`；
- 不同步时直接失败并逐条列出 `LIMIT_SYNC_MISMATCH ID n safe_max: toml=2500 pl=1500`；
- 起因：10-17 示教后只改了 toml，pkg 仍是 10-13 值，板端 `move-six` 在 CHECK_GUARD
  阶段以 `fault=12 measured_limit_rejected / write_sent=0` 拒发。**改限位 = 必须重综合 bitstream**。

### 8.1 限位有两处副本，生产板用的是包装层那份（10-19 补）

| 位置 | 谁在用 | 形式 |
| --- | --- | --- |
| `src/pl/rtl/g2_board_limits_pkg.sv` | 非 TTL 变体（`rtcs_axi_wrapper_bd` 用 `rtcs_top` 默认参数） | SystemVerilog 包 |
| `src/pl/rtl/rtcs_axi_wrapper_ttl_bd.v` | **生产板（带舵机 IO 的 TTL 变体）** | Verilog 字面量 |

BD 的 module reference 顶层必须是 Verilog(.v)，而 Verilog 不能引用 SystemVerilog 包常量，
所以 TTL 包装层只能复制一份字面量。**两处都要改，脚本两处都校验**（输出里 `sources=` 会列出
被校验的包装层文件名）。

10-17 的坑比原先判断的更靠前一层：pkg 当时已改（ID2 2500/ID4 3100），但 TTL 包装层仍是
1500/2861 —— 哪怕当时重综合了，产出的 bitstream 也还是旧限位。

### 8.2 必须用 `ttl` 变体综合

```
powershell -ExecutionPolicy Bypass -File scripts/build_vivado.ps1 -Build -Ttl
```

只带 `-Build` 生成的是**不导出舵机 IO** 的变体（XSA 约 377 KB，正常约 645 KB）：
上板后 `limits` 全为 0、`move-six` 直接 `six_axis_uncalibrated`。
判据：综合日志出现 `RTCS_G1_TTL_IO_OK tx=U20 rx=V15 inhibit=W15 pullup=TRUE`。

## 9. 补示教 approach / lift 的固定流程（10-19，19:15 修订）

**为什么必须补**：这两步现填的是复位值占位（`measured_at` 以 TODO 开头）。真跑时门禁会拒绝整份
计划——`G3_PLAN_REJECTED approach: placeholder pose; teach this station point before executing`。
这不是故障，是防止"复位值当过渡位"直接撞机的保护。

**10-19 晚实测得出的关键限制（示教前必读）**：

- 10-17 的六工位点是**逐轴 `calibrate-step` 示教**的；`move-six` 是**六轴同时广播**，
  两者轨迹不同（重力/机械耦合），所以旧点集**不能按 set 一次性到达**。实测：
  grasp `[2061,2130,2073,3009,2006]` 走 move-six 时 **ID3 在 2115 停住**（目标 2073，差 42），
  整条命令 `fault=9 fault_id=3`。
- **ID2 在机械臂展开时，约 1990 处是"竖直点"（连杆与底座垂直）**：单轴从 2130 往回退
  到 1950，两次都静默停在 1987 / 1991（无 servo_error），即**越点后带末端负载回不来**。
  **定案（10-19）：所有运动位点 ID2 目标 ≤ 2000，全程不跨竖直点**；grasp 不再用 2130，
  改在竖直点近侧取 2000，抓取位置不够就由人挪动传送带补偿。门禁已固化（`id2_target_max=2000`），
  ID2 > 2000 的计划会被拒。
- 夹爪闭合 `--id 6 --target 2200` → `fault=5 + servo_error_raw=0x20 + last≈2368`，与设计一致：
  过载=夹住了（CONTACT 语义在实机验证通过）。

**因此示教原则改为：一切位点都用 `move-six` 实测可达值；approach/lift 用"小幅可达偏移"，不跨 ID2 竖直点。**

前提：新 bitstream 已上板（`limits` 里 ID2 max=2500、ID4 max=3100）。

```sh
# 0) 只读确认 + 急停手段
sudo rtcs-pl-g2-six --uio /dev/uio0 limits      # ID2 max=2500  ID4 max=3100
sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose    # 六轴 servo_error 全 0
sudo rtcs-pl-g2-six --uio /dev/uio0 stop --execute   # 随时"读后原地保持"

# 1) 用 move-six 逼近抓取位，读"实际到达值"而非命令值
#    ID2 用 2000（竖直点近侧），不再用 2130；其余轴按实测可达值逐步逼近。
sudo rtcs-pl-g2-six --uio /dev/uio0 move-six \
  --axis 1:2061:500:10 --axis 2:2000:500:10 --axis 3:2115:500:10 \
  --axis 4:3009:500:10 --axis 5:2006:500:10 --axis 6:2500:500:10 \
  --observe-ms 8000 --execute
sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose    # 把这条 diagnose 的六轴值当作 grasp 位

# 2) 找 approach：从 grasp 位小幅抬起，逐个轴探测"哪根轴能让夹爪抬高"
#    一次只动一根轴 +50~80 count，动完 diagnose 看夹爪是否抬离工件；找到抬升轴后记录整组值。
#    ID2 保持 ≤2000 不动；优先试 ID3 / ID4。
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 3 --target 2165 --speed-raw 500 --time-raw 10 --execute
sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose    # 读值 = approach 位

# 3) 夹紧（只动 ID6），再把抬升轴回到 approach 的读数 = lift 位
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 6 --target 2200 --speed-raw 500 --time-raw 10 --execute
#    期望 fault=5 + servo_error_raw=0x20 + last≈2367 = 夹住了
sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose    # 读值 = lift 位
```

> **place 位同样要重测**：10-17 的 place `[1164,2433,2030,2723,2013]` 里 ID2=2433 比 grasp 的
> 2130 更靠"竖直点另一侧"，很可能也到不了；用同样的 move-six 实测法重取。

要点：

- **用"实际到达值"示教，不用"命令值"**：命令 2073 实际只到 2115，写 2073 就会每轮 fault=9；
- approach 与 lift 常常同一高度，但各测一次、各写 `measured_at`；
- **ID2 目标 ≤ 2000（门禁已强制）**，抓取位不够就挪传送带；抬升/下降优先用 ID3/ID4；
- lift 的 ID6 写实测接触值（≈2367），编排层会再按 Hold 覆盖；
- 填完后 `--once --dry-run` → `--once` → `--loop 3`（保持 `--observe-ms 8000`）；
- 若机械上 ID2 就是带不动展开臂跨竖直点，这是**机械/结构问题**（负载太重、安装位、或需要更大扭矩），
