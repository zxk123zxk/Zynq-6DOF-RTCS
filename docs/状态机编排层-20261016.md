# G3 状态机编排层 · 骨架与验收（2026-10-16）

等待相机/训练的空窗期产物：把"单循环六步"做成**参数化状态机**，一份代码同时服务
盲抓（固定示教点）和视觉抓（映射坐标）。全程不碰真舵机，离线可回归。

## 1. 新增文件与原理

| 文件 | 职责 | 原理 |
| --- | --- | --- |
| `scripts/g3_station_runner.py` | **状态机编排层（核心）** | 读已确认的 `g3_station_plan.json` → 复用 `g3_offline_plan.validate` 门禁（ID5 放行/越界/preflight/六步顺序）→ 顺序执行六步：每步 subprocess 调 `rtcs-pl-g2-six move-six`（真正的组帧/限位/总线时序在 PL）→ 解析 `RTCS_PL_G2_SIX_OK` / `ERR g2_six_fault` 判定成败 → **故障留痕不锁死**（某步失败→记故障→跳 exit 安全回位→本轮失败→下一轮继续）→ 支持 `--once` / `--loop N` / `--dry-run` / `--grasp-xy` |
| `scripts/grasp_point_map.py` | **抓取点参数化几何层** | 工作平面 `(x,y)` → 六轴 target。示教表最近邻/双线性插值（ID 1-3 随坐标变、ID 4-6 固定姿态）；`map_grasp_analytic` 精确两连杆解留 TODO 待工位几何实测 |
| `sim/run_g3_station_runner_guard.sh` | **离线回归** | mock 的 move-six（Python 脚本），测四件事：①六步顺序 ②故障不锁死（grasp 失败→exit 回位→第二轮跑通）③越界计划被拒 ④`--grasp-xy` 覆盖抓取点 |

## 2. 数据流

```
visual (u,v) ─plane_mapping.py─> (x,y)
                                    │
grasp_point_map.map_grasp(x,y,table,fixed_pose) ──> 六轴 target（覆盖 approach/grasp/lift 的 ID1-3）
                                    │
g3_station_runner.py ──> 每步 move-six ──> rtcs-pl-g2-six ──> PL（组帧/限位/总线）
      │（盲抓时跳过映射，直接用计划里的固定示教点）
      └─ 六步：standby → approach → grasp → lift → place → exit
```

## 4. 板端部署（从零到跑通，任何人按此操作即可）

### 4.1 准备（Windows 开发机）

新镜像三件套已在 `artifacts/sd/`（已含 python3）：

| 文件 | 说明 |
| --- | --- |
| `artifacts/sd/BOOT.BIN` | 5.2MB |
| `artifacts/sd/image.ub` | 27.8MB（含 python3 3.10.6） |
| `artifacts/sd/boot.scr` | 启动脚本 |

再把以下文件也一起拷进 SD 卡 FAT32 分区（作为搬运介质）：

```
scripts/g3_station_runner.py
scripts/g3_offline_plan.py
scripts/grasp_point_map.py
config/g2_measured_limits.toml
config/g3_station_plan.template.json      # 链路验证用
config/g3_station_plan.json               # 六步示教实测后填实（正式运行用）
config/grasp_teaching_table.json          # 视觉抓可选
```

> 复制完务必在 Windows 里**右键“安全弹出”**再拔卡，否则数据可能没落盘。

### 4.2 烧录 + 启动

SD 卡插入板端，**断电重插冷启动**（不是 reboot）。

### 4.3 板端验证

```sh
python3 --version        # 期望：Python 3.10.6
mount | grep ' / '        # 看根文件系统是 RAM 还是 SD 分区（判断脚本断电是否丢失）
```

### 4.4 脚本上板（每次开机执行一次）

```sh
mkdir -p ~/rtcs/scripts ~/rtcs/config && \
cp /run/media/mmcblk0p1/g3_station_runner.py /run/media/mmcblk0p1/g3_offline_plan.py /run/media/mmcblk0p1/grasp_point_map.py ~/rtcs/scripts/ && \
cp /run/media/mmcblk0p1/g2_measured_limits.toml /run/media/mmcblk0p1/g3_station_plan.template.json ~/rtcs/config/
cd ~/rtcs
```

> 挂载点 `/run/media/mmcblk0p1` 可能随板端变化；先 `ls /run/media/mmcblk0p1/` 确认
> （普通用户看不到内容就用 `sudo ls`）。若已填实 plan，把上面的
> `g3_station_plan.template.json` 换成 `g3_station_plan.json`。

### 4.5 链路验证（用未填实的模板，理应被门禁拒绝）

```sh
cd ~/rtcs
python3 scripts/g3_station_runner.py config/g3_station_plan.template.json --once --dry-run
```

期望输出：

```
G3_PLAN_REJECTED station/workspace: operator confirmation missing
```

看到“被拒”就是对的——python3 + 三脚本 + 限位表 + 门禁校验全链路通了（模板未填实，本就该被拒）。

### 4.6 正式运行（填实 `g3_station_plan.json` 之后）

```bash
# 盲抓：先 dry-run 打印六步命令人工审阅
python3 scripts/g3_station_runner.py config/g3_station_plan.json --once --dry-run
# 盲抓：跑一遍
python3 scripts/g3_station_runner.py config/g3_station_plan.json --uio /dev/uio0 --once
# 盲抓：连续 10 轮（11.04 兜底视频）
python3 scripts/g3_station_runner.py config/g3_station_plan.json --uio /dev/uio0 --loop 10
# 视觉抓（映射坐标覆盖抓取点）
python3 scripts/g3_station_runner.py config/g3_station_plan.json --uio /dev/uio0 \
    --grasp-xy 120.5,-30.0 --teaching-table config/grasp_teaching_table.json --once
```

### 4.7 修改闭环（别在板端改，正本在仓库 git）

板端 rootfs 若为 RAM，`~/rtcs` 断电即丢。修改流程固定为：

1. 在开发机改仓库里的脚本/配置；
2. 拷到 SD 卡 FAT32 分区（安全弹出）；
3. 板端重跑 §4.4 的 sync 命令；
4. 重跑 §4.6。

这样正本永远在仓库，板端只是每次开机的临时副本。

## 6. 安全边界（与现有红线一致）

- 编排层**不发任何一帧**，只调 `rtcs-pl-g2-six`（帧由 PL 拼、限位由 PL 裁）；
- 越界/未放行 ID5/缺 preflight 的计划在 `validate` 阶段即被拒，不会执行任何运动；
- exit 步回位失败 → 立即终止（安全无法保证时不硬继续）；
- 单步故障如实留痕、不锁死后续轮次，但**不自动重试**同一命令。
