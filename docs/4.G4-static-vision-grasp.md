# G4：相机标定与视觉引导静态抓取

**状态：未开始。** 入口是 [G3](3.G3-static-closed-loop.md) 的单循环跑通。本阶段结束时，系统能在固定平面上识别随机摆放的物体并自动抓取。

## 相机与方案选型（已定）

| 项 | 取值 |
| --- | --- |
| 相机 | 幻尔（Hiwonder）USB 高清广角摄像头，**30 万像素 / 120° 视场角**，免驱 UVC |
| 分辨率 | 约 640×480（VGA）；实际上板以 `v4l2-ctl --list-formats-ext` 实测为准 |
| 接口 | USB，走 V4L2/UVC；PetaLinux rootfs 需确认含 `uvcvideo`（队友已在 PC 上装好 OpenCV 并可用该相机取流） |
| **深度** | **无深度图** |
| 工件 | 3D 打印小方块（体积小、纹理弱、颜色可控） |

**⚠️ 120° 广角是必须处理的约束。** 视场角越大，桶形畸变越强、边缘像素密度越低。因此：

1. **内参标定必须同时求畸变系数**（`cv2.calibrateCamera` 的 `dist`），检测前先用 `cv2.undistort` 校正，否则边缘区域的定位误差会达到厘米级。
2. **把工作平面限制在图像中央区域**（约中央 60%），边缘的畸变残余与像素密度都最差。
3. **相机架高要权衡**：架得高 → 视野覆盖大但每毫米的像素数少；架得低 → 精度高但覆盖小。按"抓取平面在工作视野内占中央 60%"来定高度。
4. 3D 打印小方块**纹理弱**，纯轮廓/颜色阈值可能不稳；**优先准备 ArUco 标记兜底**（贴在方块顶面），它同时给出位置与朝向，且对光照不敏感。

**由此确定三条不可动摇的方案结论：**

1. **不使用点云、不使用 GraspNet/Graspness 等深度学习抓取检测。** 无深度相机，且该网络需要 CUDA + MinkowskiEngine + 完整 GraspNet 数据集，在 Zynq ARM 上不可运行。素材库 `Material_Library/机械臂ROS入门教程-小五/graspness_/` 的**网络部分明确不采用**。
2. **使用单目 2D + 平面假设。** 抓取发生在同一高度的平面（桌面或传送带面）上，因此只需把**像素坐标**映射到**工作平面坐标**。
3. **视觉只需输出三个量：平面的 (x, y) 与绕竖直轴的偏航角 yaw。** 因为 ID 1–5 是关节、ID 6 是夹爪，自上而下抓取所需的高度是常量（由示教确定），姿态只需 yaw 由 ID 5 承担。

## 实施步骤

### 步骤 1：相机接入 PS（半天）

- 确认板端枚举：`ls /dev/video*`；用 `v4l2-ctl --list-formats-ext` 记录实际支持的分辨率与帧率。
- 若 rootfs 缺 UVC 支持，需在 PetaLinux kernel 配置补 `CONFIG_USB_VIDEO_CLASS` 并重建镜像（这会改 kernel，不算 ABI 变更）。
- 取流程序：先写一个最小 C/C++ 或 Python 采样程序，能存单帧 PNG。
- 产出：一张能看清工作平面的实拍图 + 板端取流日志。

### 步骤 2：相机内参标定（半天）

- 打印棋盘格（建议 9×6，方格 20 mm），用 OpenCV `findChessboardCorners` + `calibrateCamera` 求内参与畸变系数，存 `config/camera_intrinsics.yaml`。
- 参考实现：`Material_Library/机械臂ROS入门教程-小五/graspness_/utils/data_utils.py` 的 `CameraInfo` 结构；标定流程可参考同目录 `real/calibrate.py` 的棋盘格采集部分。
- 产出：标定结果 + 重投影误差（target < 0.5 px）。

### 步骤 3：平面映射标定（关键，1 天）

**竞赛推荐方案：单应矩阵（homography），而不是完整 3D 手眼标定。**

- 把棋盘格平放在**抓取工作平面**上（高度与物体顶面一致）。
- 机械臂末端（或夹爪尖端）依次移动到平面上 ≥6 个**已知工作坐标**的位置，同时拍一张图，记录该位置在图像中的像素坐标。
- 用 `cv2.findHomography`（或 DLT 解 8 参数）求 **像素 → 工作平面** 的 3×3 矩阵，存 `config/homography_plane.yaml`。
- 校验：任取 3 个未参与拟合的点，检查映射误差（target < 2 mm）。
- **参考**：`graspness_/real/calibrate.py` 用 SVD 求 3D 刚体变换的思路可用于多平面/倾斜场景；但本项目只需要平面映射，**不必引入它的 3D 复杂度**。若相机与平面不垂直、存在透视，用 homography 依然正确。

> 为什么不用 `calibrate.py` 的完整方案：它要机械臂在 3D 空间走一个网格并求 `camera_pose`，是为 UR5 的多平面抓取设计的。我们用固定高度的平面抓取，单应矩阵更简单、更准、更快标定。

### 步骤 4：目标检测（1–2 天）

- 首选**经典视觉**：`cv2.inRange` 颜色阈值（HSV）或轮廓提取 → 连通域 → 取质心（像素 x,y）与最小外接矩形的角度（yaw）。
- **兜底方案**：若物体颜色/光照不稳定，给物体贴 **ArUco 标记**，`cv2.aruco` 直接给出稳定的位置与朝向，鲁棒性远高于颜色阈值。竞赛现场强烈建议准备这个兜底。
- 参考：`Material_Library/kr260_robotic_arm-main/opencv_ros2/`（颜色识别→抓取的完整思路，注意它是 ROS2，需改写为独立进程）。
- 产出：对随机摆放物体输出 `(u, v, yaw)` 的检测程序 + 一张标注图。

### 步骤 5：位姿生成与集成（1–2 天）

- `(u, v) → (x, y)`（homography）→ 关节目标：
  - 位置：由 `(x, y)` 与固定抓取高度反解 **ID 1–3**（可用两连杆几何解析解，或对示教表做插值）。
  - 姿态：`yaw → ID 5` 目标；ID 4 保持示教常量。
  - 夹爪：ID 6 给"开"目标；抓取步给"合"目标。
- 把 G3 的六步状态机扩展为：**拍照 → 检测 → 坐标映射 → 生成六轴目标 → 执行接近/抓取/抬升/放置**。
- 产出：一条命令即可完成"看一眼然后抓"的完整流程。

## G4 验收标准

| 级别 | 标准 |
| --- | --- |
| 最低 | 相机取流 + 检测输出正确 `(u,v,yaw)`（不接机械臂） |
| 目标 | **视觉引导静抓 ≥8/10 成功**，物体随机摆放在工作平面内 |
| 理想 | ≥9/10，且定位误差 < 3 mm、单次"看-抓"耗时 < 5 s |

## 风险与降级

- **若视觉未按期达成**：11.04 直接使用 G3 的固定工位抓取视频交付（见[总规划](0.1hardware_bringup.md)的降级路径），视觉顺延到决赛前完成。
- **若光照不稳定**：立刻切 ArUco 兜底，不要花时间调颜色阈值。
- **若板端 UVC 不支持**：先用一台 PC 跑视觉，通过网口/串口把 `(x,y,yaw)` 发给板端执行；这条路径仍然满足"视觉引导抓取"，只是算力位置不同。**这不需要改 PL，是最省时的兜底。**

## 阶段边界

- 视觉只是"提供目标坐标"的输入源；**不得替代 PL 的限位、截止时间与急停职责**。
- 检测失败、置信度低、映射误差超限时，必须**放弃本次抓取**而不是猜一个目标下发。
