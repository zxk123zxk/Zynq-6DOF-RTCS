## 队友交付的接口契约（V1.1，勿自行改动）

```python
from vision import Detector
from integration import to_ps_payload
from vision.plane_calibration import PlaneCalibration

cal = PlaneCalibration.load(Path("config/calibration.json"))
payload = to_ps_payload(Detector(device="cpu").detect(frame), cal)
# payload["detections"][i]["center_x_mm"], ["center_y_mm"]  ← 传送带平面毫米坐标
# payload["detections"][i]["bbox_mm"]["width"/"height"]      ← 可用于粗算物块尺寸/朝向
```

**坐标系定义**：原点 = 传送带左下角，`+x` 沿传送带长度方向、`+y` 沿宽度方向（单位 mm）。
**示教表必须建在同一坐标系下**，否则映射会整体偏移。

**四条已知限制（写进 11-04 文档，不能含糊）**：

1. 训练 73 张 / 验证 30 张，且验证集用于早停与选权重，**不是独立测试**；80 张同源基线图里
   7 个 Cube→Cylinder 错分类。跨机位、跨光照准确率未验证。
2. 未做镜头畸变校正；**物体高出标定平面时有视差**——物块自身有高度，这是系统性误差。
3. 只输出平面毫米坐标，**不含 yaw**；`bbox_mm` 可粗算朝向但未验证。
4. 标定板 490×80 mm 只是一条窄带，**带外外推不可信**。

## 相机与方案选型（已定）

| 项 | 取值 |
| --- | --- |
| 现役相机 | **中奥维柯 3 mm / 90° 无畸变 UVC + CPL 偏振片**（2026-10-17 到货，替换原 120° 广角） |
| 实测格式 | **1280×720 / YUY2 / dshow，设备号 1**（`grasp_point.py` 默认值；设备 0 是另一个对着天花板的镜头） |
| 原相机 | 幻尔 30 万像素 / 120° 广角 —— 桶形畸变与镜面高光不可控，已弃用 |
| 接口 | USB，走 V4L2/UVC |
| **深度** | **无深度图** |
| 工件 | 40 mm 3D 打印方块（体积小、纹理弱、颜色可控） |

**换机原因（2026-10-15 现场定案，不要回退）**：绿带白方块在光面 PVC 皮带上不可检，
根因是镜面高光 + 自动曝光过曝（白高光冒充 Cube、淹没真方块）；桌面哑光所以正常。
治理顺序走过"压曝光 → 调灯/角度"，最后由换 90° 无畸变镜头 + CPL 解决。
**换相机 = 工况重置**，旧机位上的标定与训练数据全部作废，这是 10-17 之后重新标定的原因。

**⚠️ 镜头畸变仍是必须处理的约束。** 即使换了 90° 镜头，仍按下面的做法处理：

1. **不做独立的内参/畸变标定，改为在实际工作平面上直接测量映射**（2026-10-14 决定）。平面上实测的点对会把镜头畸变一起吸收进映射本身；代价是映射只在该平面、该已验证区域内有效，越界必须拒绝而不是外推。
2. **把工作平面限制在图像中央区域**（约中央 60%），边缘的畸变残余与像素密度都最差。
3. **相机架高要权衡**：架得高 → 视野覆盖大但每毫米的像素数少；架得低 → 精度高但覆盖小。按"抓取平面在工作视野内占中央 60%"来定高度。
4. **背景固定为两种工况：黄色桌面 或 绿色传送带。** 只有这两种背景需要保证检出；不做通用背景鲁棒性，也不为其它背景调参。
5. 3D 打印小方块纹理弱；现有 YOLO 已承担类别与像素中心检测。

**为什么放弃棋盘格（2026-10-14 决定，不要重新引入）**

- 2026-10-13 现场实测：打印棋盘格（9×6 内角点、25 mm 方格）受遮挡、反光与广角畸变影响，`findChessboardCorners` 未能稳定检出；同期 YOLO 在最终要求的**绿色传送带上**对黑方块检出正常（当帧置信度约 0.86 / 0.36）。棋盘格画面反而出现大量误检。
- 由此砍掉整条棋盘格路线：**不打印标定板、不跑角点检出、不单独求内参/畸变**。原 `scripts/vision/check_chessboard.py` 已删除。
- 若后续确需姿态估计，必须另行定义、实现并验证；它不是当前前置工作。

**由此确定三条不可动摇的方案结论：**

> **2026-10-15 补充**：操作者提出与"手眼标定+数据训练"（SO-ARM101.pdf 的 LeRobot/ACT 模仿学习教程）路线的对比。已逐维度评估，**维持固定机位+平面映射主线**：模仿学习需主臂、episodes、云 GPU 且与 Zynq 直驱架构冲突，20 天硬节点下无容错。详见 [方案对比](vision/方案对比-平面映射vs模仿学习-20261015.md)。

1. **不使用点云、不使用 GraspNet/Graspness 等深度学习抓取检测。** 无深度相机，且该网络需要 CUDA + MinkowskiEngine + 完整 GraspNet 数据集，在 Zynq ARM 上不可运行。素材库 `Material_Library/机械臂ROS入门教程-小五/graspness_/` 的**网络部分明确不采用**。
2. **使用单目 2D + 平面假设。** 抓取发生在同一高度的平面（桌面或传送带面）上，因此只需把**像素坐标**映射到**工作平面坐标**。
3. **视觉只需输出三个量：平面的 (x, y) 与绕竖直轴的偏航角 yaw。** 因为 ID 1–5 是关节、ID 6 是夹爪，自上而下抓取所需的高度是常量（由示教确定），姿态只需 yaw 由 ID 5 承担。

## 实施步骤

### 步骤 1：相机接入 PS（半天）

- 确认板端枚举：`ls /dev/video*`；用 `v4l2-ctl --list-formats-ext` 记录实际支持的分辨率与帧率。
- 若 rootfs 缺 UVC 支持，需在 PetaLinux kernel 配置补 `CONFIG_USB_VIDEO_CLASS` 并重建镜像（这会改 kernel，不算 ABI 变更）。
- 取流程序：先写一个最小 C/C++ 或 Python 采样程序，能存单帧 PNG。
- 产出：一张能看清工作平面的实拍图 + 板端取流日志。

### 步骤 2：场景锁定 + 背景基线（半天）

**不做内参标定**（棋盘格路线已废，见上）。这一步的目标是把"相机与场景"变成可复现的固定工况，并留下两种背景的实拍基线：

- 固定相机支架、镜头、焦距、分辨率与曝光（关闭自动曝光/自动白平衡，或记录锁定值），记录安装高度与俯视角度。
- 分别在**黄色桌面**与**绿色传送带**两种背景下实拍若干帧，各存一份不含物体的背景图与一份含工件的实拍图。
- 用现有 YOLO 在这两种背景上各跑一遍，记录检出/漏检/误检的**原始样本**（不要只留成功帧）。判据是"这两种工况下能不能稳定检出目标"，不是通用背景精度。
- 产出：相机与场景配置记录 + 两种背景的背景图/实拍图 + 该工况下的检出观察记录。

### 步骤 3：平面映射标定（✅ 已完成，队友 V1.1 交付 `calibration.json`）

**竞赛推荐方案：用平面上已知坐标的点对求映射，不使用棋盘格。**

- **点的来源**：在抓取工作平面上用卷尺/直尺标出 ≥6 个**已知工作坐标**的位置（在桌面上可贴标记纸或用卡尺定位；传送带上按带面实测距离标记）。把工件依次放在这些位置上，**用现有 YOLO 读出该位置的像素中心 `(u,v)`**，得到 `(u,v) ↔ (x_mm,y_mm)` 点对。这样点对直接来自真正要用的检测器，不引入第二套角点检测。
- **求解**：点对 ≥6 且分布铺开时用 `cv2.findHomography`；只在中央区域铺 3×3 网格时，**双线性插值**比单个单应更能吸收广角畸变，二者都可行，按实测误差选。
- **校验**：任取 ≥3 个**未参与拟合**的点，检查映射误差（target < 2 mm），并记录 mean/RMS/max。
- **有效性边界**：只保证已验证点所围成的凸包内部；凸包外、分辨率不一致或配置变化时必须拒绝转换，不外推。
- 存 `config/workspace_plane.yaml`（含点对清单、求解方法、验证点误差、配置版本）。
- **参考**：`Material_Library/机械臂ROS入门教程-小五/graspness_/real/calibrate.py` 用 SVD 求 3D 刚体变换的思路可用于多平面/倾斜场景；本项目只需平面映射，**不必引入它的 3D 复杂度**。

### 步骤 4：目标检测（✅ 已完成，队友 V1.1 交付 `best.pt`）

- **现有入口是 YOLO**：`src/vision/` 已能识别方块和圆柱体并输出原图像素中心 `(u,v)`；黑方块及后续更小黄方块需在最终相机安装和工作台光照下另行实拍验证。
- **只对两种固定背景负责：黄色桌面、绿色传送带**（2026-10-14 决定）。不在这两种背景上的画面不作为验收对象，也不为它们调参。
- 当前模块不输出 `yaw`。如抓取确需朝向，再从检测框/轮廓或标记估计并验证；不能把 YOLO 像素中心直接写成工作台毫米坐标。
- 参考：`Material_Library/kr260_robotic_arm-main/opencv_ros2/`（颜色识别→抓取的完整思路，注意它是 ROS2，需改写为独立进程）。
- 产出：两种背景下物体的 `(u,v)` 检测记录与标注图；`yaw` 为后续增量。

### 步骤 5：mm → 六轴目标（✅ 已完成，6 点五轴示教表）

**不写 IK，用示教点表沿 x 分段线性插值。** 理由：竞赛工位固定、抓取高度单一，
示教表在已覆盖区间内精度足够；解析 IK 要标定量杆长度/零点/耦合，风险与工期都划不来。

**怎么录（不要手编 JSON）**：用 `scripts/teach_add_point.py`，它读 `diagnose` 取 ID1-5，
按 x 排序去重。**默认五轴**，因为 ID4/ID5 是腕部姿态——教点时臂停在什么腕姿，
运行时就该是什么腕姿；三轴格式会让运行时用计划里的固定腕姿，实测差 150~250 count。

```sh
sudo python3 scripts/teach_add_point.py --x-mm 295 --y-mm 36   # 依次录 6 个点
```

当前定表（2026-10-25 收盘，`config/grasp_teaching_table.json`，正本）：

| x_mm | ID1 | ID2 | ID3 | ID4 | ID5 |
| --- | --- | --- | --- | --- | --- |
| 295 | 1699 | 2109 | 2141 | 2923 | 1687 |
| 320 | 1806 | 2030 | 2226 | 2885 | 1706 |
| 345 | 1854 | 2010 | 2241 | 2942 | 1757 |
| 370 | 1937 | 1971 | 2296 | 2972 | 1845 |
| 395 | 2039 | 1965 | 2287 | 2932 | 1950 |
| 420 | 2185 | 1912 | 2369 | 2873 | 2107 |

- 坐标用**传送带系统**（原点=带角，+x 沿带长、+y 沿带宽），与 `calibration.json` 同源；
- **每条 `targets` 必须是现场 `diagnose` 实测值**——不准按几何比例推算后直接写
  （10-21 按增量推导 lift 撞过底座，fault=9 fault_id=4）；
- 全部点同一条车道 `y=36`，`same_lane()` 通过 → 走 `piecewise_linear`（**≥2 点即真插值**）。
  三点表时代 bilinear 会退化成最近邻，误差可达间距一半，这是 10-22 的坑；
- **两端夹住、不外推**：x 越界时直接用端点姿态并打印 `G3_WARN grasp-xy x=… outside taught range`。
  外推不安全——ID2 逐点斜率是 −3.16/−0.80/−1.56/−0.24/−2.12（正负交替），
  说明曲线不光滑，按末段斜率外推会偏离 100 count 量级。

**使用方法**：

```sh
sudo python3 scripts/g3_station_runner.py config/g3_station_plan.json --uio /dev/uio0 \
    --grasp-xy 345,36 --teaching-table config/grasp_teaching_table.json --once
```

`apply_grasp_point` 实际覆盖的不止 ID1-3：**五轴表下 ID1-5 全部按表插值**，
再叠加三条硬约束——

1. `lift` 的 **ID1 锁抓取值**（离地之前不许横向移动，水平位移交给 `place`）；
2. `lift`/`place` 的 **ID4/ID5 继承抓取点**（`carry_wrist`，否则搬运中腕部自转把方块拧掉）；
3. `place` 拆两段：**ID1 单轴先横摆（保持高位）→ 六轴联动下放**。

**接视觉**：PC 侧 `vision_v11/.../scripts/grasp_point.py`，
把输出的 `x_mm / y_mm` 直接作为 `--grasp-xy` 的两个参数。它一次做四件事：
多帧中位数出点、验带面是否还在标定位置（`belt_iou`）、软 ROI（只在带面四边形内选目标）、
打印可直接粘贴的板端命令。完整流程见 [视觉到抓取端到端流程](视觉到抓取端到端流程.md)。

**有效性边界**（必须写进报告，别含糊）：

- 只保证 x ∈ [295, 420]；越界夹端点，会偏 20 mm 以上（方块只有 40 mm，等于抓空）。
- **y 不参与插值**：`piecewise_linear` 只读 x。件摆偏离车道 y=36 多少，落点就错多少，
  与视觉无关。所以"随机摆放"只能随机 x，y 必须守在 36±5 mm。
- **精度上限由教点重复性决定，不是算法**：ID2/ID3 逐点斜率正负交替，说明手工摆位的
  重复性在 ±10 mm 量级。40 mm 方块能吃掉这个误差，换小件就会失效。

## G4 验收标准

| 级别 | 标准 |
| --- | --- |
| 最低 | 相机取流 + 现有 YOLO 输出正确 `(u,v)`（不接机械臂）；`yaw` 是后续增量 |
| 目标 | **视觉引导静抓 ≥8/10 成功**，物体随机摆放在工作平面内 |
| 理想 | ≥9/10，且**落点偏差 ≤10 mm（教点重复性上限）**、单次"看-抓" ≤ 5 s |

> "定位误差 <3 mm" 的早期写法已作废：手工示教的重复性撑不到 3 mm，
> 该指标要等落点测量闭环或工装定位才能谈。

## 风险与降级

- **若视觉未按期达成**：11.04 直接使用 G3 的固定工位抓取视频交付（见[总规划](0.1hardware_bringup.md)的降级路径），视觉顺延到决赛前完成。
- **若现场识别不稳**：先保留现有 YOLO 输出及失败样本，按实际误检/漏检决定补样本或启用标记方案。
- **⚠️ 若演示现场背景不是黄色桌面或绿色传送带**（例如换了桌布、加了遮光布）：视觉不在验收范围内，**必须走降级路径**——先用 G3 固定工位抓取，或现场把背景恢复成已验收的两种工况之一。不要为了"救场"临时在未标定的背景上调参。
- **若板端 UVC 不支持**：先用一台 PC 跑视觉，通过网口/串口把 `(x,y,yaw)` 发给板端执行；这条路径仍然满足"视觉引导抓取"，只是算力位置不同。**这不需要改 PL，是最省时的兜底。**

## 阶段边界

- 视觉只是"提供目标坐标"的输入源；**不得替代 PL 的限位、截止时间与急停职责**。
- 检测失败、置信度低、映射误差超限时，必须**放弃本次抓取**而不是猜一个目标下发。
