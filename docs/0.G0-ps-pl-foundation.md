# 0. G0：PS-PL 基础工程（已通过）

G0 证明 AX7Z020B 可以在**不连接舵机**的安全边界内启动，并建立 PS 到 PL 的基础控制通路。它不是机械臂运动阶段。**本阶段已通过**（后续 ABI 迭代只扩展了可写通路的范围）。

## 本阶段核心改动

- 完成板卡型号、PL Bank 电压、收发器逻辑电平、独立舵机电源、共地和硬件急停的 G0 核验；舵机当时保持断开。
- `src/pl/vivado/ax7z020b_ps7_config.tcl` 固化 PS7：DDR3 1 GiB（两片 MT41J256M16，32 位，533.333 MHz）、PS UART1、SD0、PS USB0 Host（MIO28..39）、`M_AXI_GP0`、`IRQ_F2P` 和 100 MHz `FCLK_CLK0`。USB0 供 G1 BusLinker Linux 基线使用。
- `src/pl/vivado/create_rtcs_system.tcl` 建立 `PS7 -> AXI Interconnect -> rtcs_axi_wrapper_bd -> rtcs_top`，并通过 `proc_sys_reset` 分发同步低有效复位。
- RTCS 的 PS 可见地址固定为 `0x43C0_0000`，窗口大小 64 KiB；设备树把它登记为 `generic-uio` 外设。
- `src/pl/rtl/axi_lite_regs.sv` 实现 AXI4-Lite 寄存器组；`sim/tb_axi_lite_regs.sv` 已覆盖复位、读写握手、部分字节写和六轴目标寄存器。
- PetaLinux 构建脚本、SD 启动脚本和 `rtcs-uart-smoke` 控制台冒烟应用已加入工程。

## 当前可用数据路径

```text
PS Linux -> M_AXI_GP0 -> AXI Interconnect -> AXI4-Lite register bank
```

软件可见寄存器以 `src/pl/rtl/rtcs_pkg.sv` 与 `src/ps/linux/include/rtcs_registers.hpp` 为唯一事实来源。关键偏移为：`ID_VERSION=0x00`、`CONTROL=0x04`、`COMMAND=0x08`、`TARGET_0..5=0x20..0x34`、`PROFILE_SPEED=0x38`、`PROFILE_ACCEL=0x3c`、`DEADLINE=0x40/0x44`、`REG_G2_DIAG=0x118`。

## 本阶段遗留项（不是当前阶段的问题）

- `CONTROL`/`COMMAND`/`PROFILE_*`/`DEADLINE`/`REG_G2_START` 是 G0 轨迹引擎的预留寄存器，被 `rtcs_registers.hpp` 与 `tb_axi_lite_regs.sv` 定义为 ABI 契约，**不可删除**；当前运动不经它们（走六轴描述符 + `REG_G2_DIAG` 诊断）。
- RTL 的 `IRQ` 输出仍恒为低；`trajectory_engine.sv` 仍是空接口。PS 侧软状态机承担任务编排。
- 默认安全 wrapper 不导出舵机 IO；只有 `scripts/build_vivado.ps1 -Build -Ttl` 才使用 TTL wrapper。
