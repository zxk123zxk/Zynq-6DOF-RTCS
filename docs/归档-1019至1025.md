## 一、PL 侧定型（10-19）

| 项 | 结论 |
| --- | --- |
| 限位三处同源 | `config/g2_measured_limits.toml`、RTL 参数包、TTL 包装层字面量**必须一致**；`scripts/check_limit_sync.py` 在打包/回归里各查一次。曾经只改 toml 导致 `fault=12` 拒发 |
| 夹爪闭合 | **拆成单轴命令**下发；舵机堵转报 `0x20` 过载是"夹住了"的正常工况，判 `CONTACT`，不是失败 |
| 夹持段 | `lift`/`place` 只动 **ID1–5，ID6 完全不参与**；否则 ID6 持续过载会被六轴命令读到，整条命令判死（`exit fault=5 fault_id=6`） |

## 二、七步闭环与四项修订（10-20）

| 修订 | 原因 | 效果 |
| --- | --- | --- |
| PL **逐轴忽略掩码 `0x11C`** | 夹紧后 ID6 过载把六轴命令拖死 | 根治"夹紧就挂" |
| 夹持期追加 `--ignore-arrival 6` | ID6 顶着物块时位置在保护区间来回漂 >100 count，仍在等"到位" → 空等满 8000 ms | 实抓/空抓响应一致 |
| 速度分级 **1000 / 1200 / 1400** | 原全部 500（PL 上限 1500） | 单轮 10.6 s → **6.1–6.8 s** |
| 新增第七步 **`retreat`** | `place` 张爪后直接 `exit`，ID1 从 2875 转到 2045 时爪仍在放置高度，扫倒刚放下的方块 | 先垂直抬 ID2/3/4，ID1 原地不动，再转基座 |

`exit` 的 ID6 取 **2619**（张开值），不能抄 lift 的接触位。

## 三、端到端首通与 `lift` 的三次踩坑（10-21）

首次打通：相机 → YOLO → 单应(mm) → 示教表 → 六轴 → PL → 舵机，**7.24 s/轮**
（`standby 985 / approach 776 / grasp 167 / gripper 1220 / lift 675 / place 985 / place.gripper 664 / retreat 883 / exit 883`）。

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| ① | `lift` 也当"随平面坐标变化的步" | ID1-3 被写成和 grasp 一样，**抬升消失**，带件横移扫到传送带 |
| ② | 按"抓取位 + 固定关节增量"推导抬升位 | 基座偏移 337 count 时末端过度伸展，**撞底座**（`fault=9 fault_id=4`） |
| ③ **采用** | **直接用计划里固定的标准抬升位** `[2045,1240,2534,3100,2005]` | 675 ms 抬升，长期全绿 |

> **规矩**：抬升位是"验证过的固定姿态"，不是算出来的。位点数值只能来自现场 `diagnose`。

环境：venv 建在 `D:\rtcs-venv`（项目路径 260 字符会撞 Windows MAX_PATH，不能用项目内 `.venv`）。

## 四、坐标系重建与五轴示教表（10-22 ~ 10-24）

**坐标系**：`scripts/belt_calibration_dynamic.py` 用 HSV 绿掩膜自动找带四角，空格冻结/保存，
产出与 `calibration.json` 同格式。`belt_detector._sort_corners()` 的角点实际顺序与注释相反，
**映射带一次镜像**（+y 指向图像下方那条边）。自洽可用，但**不要用 `490−x` 换算新旧帧**。
定案：只重贴 x/y 标签，`targets` 一个都不动（关节姿态与相机无关）。
实测锚点：原 354.9 那个物理点，重建后读作 **(395.0, 36.0)**。

**四个"抓不稳"故障链**（按发生顺序）：

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 夹住后抬升中**掉件** | 五轴表把腕姿改成逐点实测后，`lift/place` 仍用计划固定腕姿 → 搬运中腕部自转 22°（ID5 +249）把方块拧出来 | `lift/place` 的 **ID4/ID5 继承抓取点**（`carry_wrist`）；ID6 全程 `hold` |
| 2 | 抓取后**先小幅拖动** | ID1 轻载先到位、ID2 扛负载慢 → 基座先转，夹爪带件横扫（17°≈90 mm 弧） | `lift` 的 **ID1 锁抓取值**（纯垂直抬），水平位移交给 `place` |
| 3 | 放置时方块**撞传送带边缘** | `place` 一次六轴：ID1(+1021) 与 ID2(+900) 同步，基座没转到放置侧 ID2 就伸下去 | `place` 拆两段：**ID1 单轴先横摆（保持高位）→ 六轴联动下放** |
| 4 | `lift` 报 **`no_motion_ack`** | 单轴 ID2 目标落在**竖直点(~1990)死区**，静默停 | `lift` 回**六轴联动**（ID2+ID3 一起才穿得过死区）；单轴方案作废 |

> **口诀：离地之前不许横向移动；带件横摆必须保持高位；单轴 ID2 过不了竖直点。**

`run_lift` 与 `_id2_mid` 是死代码，**勿再调用**。

## 五、区间扩张、夹空判据与工具重建（10-25）

- **示教表 3 点 → 6 点**：295 / 320 / 345 / 370 / 395 / 420，y=36 单车道，全部现场 `diagnose` 实测。
- **夹空判据**：夹住 40 mm 方块堵转停 **2370–2401**；夹空一路合到 **2214**（离命令目标 2200 只差 14）。
  阈值 `GRIP_CONTACT_GAP = 60`，`G3_CYCLE` 行加 `grip=contact|empty`（dry-run 报 `dry_run`）。
  此前 10 次"忘放件"全被记成 `success=1`，肉眼分不出。
- **工具链重建**：`grasp_point.py` 与 `env.cmd` 曾在目录被整体覆盖时丢失，已按接口重写。
  新增：多帧中位数出点、`belt_iou` 对位校验、软 ROI、`--trial N` 自动归档。
- **教点重复性只有 ±10 mm**：ID2/ID3 逐点斜率正负交替（−3.16/−0.80/−1.56/−0.24/−2.12），
  不像光滑曲线。这是"抓 345 偏 10 mm"的真因，**不是插值算法**；40 mm 方块把误差吃掉了。
- 相机换装后定为 **index 1 / dshow**（index 0 是对天花板的另一个镜头）；板子控制台在 **COM8**（CP210x USB-UART）。

## 六、这段时期定下来的三条纪律

1. **位点数值只能来自现场 `diagnose` 实测**，不许按几何比例或增量推导（撞过底座）。
2. **禁止自作聪明的硬门禁**：任何会阻止既定任务继续的检查，默认只能告警（写进 `CLAUDE.md`）。
3. **短窗口平均不算证据**：成功率的分母必须含失败，不许同位置重试顶替。
