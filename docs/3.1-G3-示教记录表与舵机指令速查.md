> **物理断电**。任何 `fault`、异响、异常动作立即停止当次操作、保留原始输出，**不自动重试、

## 1. 舵机指令速查

全部命令都是 `sudo <程序> --uio /dev/uio0 <动词> [参数]`。**板端 shell 是 dash：
每条命令单独执行、不要粘贴多行循环，命令之间留几秒。**

| 命令 | 用途 | 发运动帧？ | 典型调用 |
| --- | --- | --- | --- |
| `rtcs-pl-g2 … probe` | 读 ABI + UIO 映射是否正常 | 否 | `sudo rtcs-pl-g2 --uio /dev/uio0 probe` |
| `rtcs-pl-g2-six … limits` | 读六轴**编译期**限位/参考位/速度上限 | 否 | `sudo rtcs-pl-g2-six --uio /dev/uio0 limits` |
| `rtcs-pl-g2-six … diagnose` | 逐轴只读位置 + 逐轴故障解释 | 否 | `sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose` |
| `rtcs-pl-g2-six … torque-status` | 读某轴扭矩开关（`0x28`） | 否 | `sudo rtcs-pl-g2-six --uio /dev/uio0 torque-status --id 5` |
| `rtcs-pl-g2 … release` | 卸力（断扭矩） | **是**（需 `--execute`） | `sudo rtcs-pl-g2 --uio /dev/uio0 release --id 5 --execute` |
| `rtcs-pl-g2 … move` | **单轴**绝对目标 | **是** | `sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 1500 --speed-raw 500 --time-raw 100 --execute` |
| `rtcs-pl-g2-six … calibrate-step` | **单轴相对**步进（`--delta -50..50`，仅 ID 2–6） | **是** | `… calibrate-step --id 5 --delta 20 --execute` |
| `rtcs-pl-g2-six … move-six` | **六轴同步**绝对目标（广播，无 ACK） | **是** | 见 §5 |
| `rtcs-pl-g2-six … stop` | 读当前位置后原地保持（不是断力） | **是** | `sudo rtcs-pl-g2-six --uio /dev/uio0 stop --execute` |

只读命令（`probe` / `limits` / `diagnose` / `torque-status`）**不接受 `--execute`**；
带运动帧的命令**必须显式 `--execute`**，且全部经过 PL 的限位/速度/截止时间/总线互斥检查。

## 2. 必须先搞清的四个概念

- **count 不是角度。** `config/g2_measured_limits.toml` 里 `counts_per_90_degrees_approx = 1000`
  只是换算**近似值**。一切限位、参考位、工位点都必须来自**实测**，禁止用角度推算或用旁边轴抄。
- **限位是编译期常量。** `limits` 读出来的是 bitstream 里那份，不是运行时写的。改限位要重综合镜像。
  当前仓库镜像 ID 6 是 `2050–3000`，但**板端上一次读回仍是旧值 `1585–2500`**——上板第一件事就是核对。
- **`speed-raw` / `time-raw` 直接进舵机帧的参数域**（PL 寄存器 `PARAM0` 低/高 16 位）。
  本仓库实测推荐 `500 / 10`；`speed-raw_max = 1500` 是 PL 编译期上限。
  **不要凭直觉猜语义或拿大速度去"顶"**——语义以 HX-30HM 协议文档为准。
- **"伺服到位" ≠ "实物夹住"。** G3 要分别记录 `target / last / target_error / fault` 与
  **实物是否真的被夹稳**。夹爪 `2100` 夹黑方块时约 2373 接触并报 `0x20`(过载)——
  这是"实物夹住 + G2 命令失败"两条并存的事实，不许把 `0x20` 改写成 `fault=0`。

### 任务「我」：ID 5 真实可用区间确认

**为什么要做**：`config/` 里 ID 5 的 `0–4000` 是**命令范围标注，不是实测安全区间**。
工位路径一旦规划到没测过的位置，就是拿没验证过的边界去撞机械干涉。

**只确认上下界，不要求走到极限。** 分 4 步，每步都有原始输出。

**第 0 步（每次上板必做）**

```sh
sudo rtcs-pl-g2-six --uio /dev/uio0 limits
sudo rtcs-pl-g2-six --uio /dev/uio0 diagnose
```

期望：`calibrated_mask=0x3f`、六轴 `servo_error=0x00`、末行 `..._DIAG OK issues=0 read_only=1 write_sent=0`。

**第 1 步：从当前位置小步外扩**（每条单独执行，间隔几秒）

```sh
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 1800 --speed-raw 500 --time-raw 100 --execute
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 1500 --speed-raw 500 --time-raw 100 --execute
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 1200 --speed-raw 500 --time-raw 100 --execute
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 2200 --speed-raw 500 --time-raw 100 --execute
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 2500 --speed-raw 500 --time-raw 100 --execute
sudo rtcs-pl-g2 --uio /dev/uio0 move --id 5 --target 2800 --speed-raw 500 --time-raw 100 --execute
```

**判读与判停**

| 输出 | 含义 | 动作 |
| --- | --- | --- |
| `RTCS_PL_G2_OK … fault=0` | 该目标可达 | 记为**已验证**，继续下一档 |
| `ERR g2_fault=8 … servo_error_raw=0xNN` | 帧已发出，**舵机拒绝** | **停止该方向**，回退到上一个成功值 |
| `ERR g2_fault=5 … write_sent=0` | 未发帧（发前 READ 门禁） | 隔久一点重跑一次；仍失败就记录并停止 |

**第 2 步：把结论写进 `config/g2_measured_limits.toml` 的 ID 5 注释块，只写实测值 + 证据来源**：

```
# 2026-10-14 实测：向下确认到 1200 可达、900 被拒 -> 下界待定于 (900, 1200]；
# 向上确认到 2800 可达、3100 被拒 -> 上界待定于 [2800, 3100)。
# 证据：artifacts/reports/id5-range-20261014.txt
```

**第 3 步**：把两轮命令的**完整原始输出（成功与失败都留）**存到
`artifacts/reports/id5-range-20261014.txt`。

**不要做**：不冲到端点值、不自动重试、不放宽容差、不把"没测到的"写成实测。

## 4. 六工位示教记录表（现场手填）

**做法**：手动把机械臂摆到目标姿态（或逐步 `move-six` 逼近）→ `diagnose` 读六个位置 →
把**六个原始 count** 抄进表里。**不要用角度推算，不要抄别的工位。**

| 步骤 | 含义 | ID1 | ID2 | ID3 | ID4 | ID5 | ID6 | 测时 | 路径畅通 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `standby` | 待机（所有步的前后都回到这里） | | | | | | | | ☐ | |
| `approach` | 接近（工件正上方，安全高度） | | | | | | | | ☐ | |
| `grasp` | 抓取（下到接触高度 + 夹爪合） | | | | | | | | ☐ | **必须实测"夹住且夹稳"** |
| `lift` | 抬升（离开台面） | | | | | | | | ☐ | |
| `place` | 放置（料盒上方 + 夹爪开） | | | | | | | | ☐ | |
| `exit` | 退出（离开料盒） | | | | | | | | ☐ | |

**填表要点**

- `grasp` 步的判据是**实物被稳定夹持**，不是位置反馈好看。不同尺寸工件接触 count 不同，
  不要求找一个对所有物体都无过载的固定闭合点。
- **ID 6 既是第 6 个轴也是夹爪**，共用同一条六轴广播命令：待机/接近步 ID 6 保持"开"，
  抓取步给"合"的目标值。**不要为夹爪另建旁路。**
- 建议布局：工件放在传送带中段固定工装内；`place` 位为侧边料盒。
- 表填完后可转录进 `config/g3_station_plan.template.json`（归档轨，**不阻塞竞赛轨**）。

## 5. 六步单循环命令模板

逐步下发，每步之间由操作者确认工件与路径状态。**一次提交最多一帧、不自动重试。**

```sh
sudo rtcs-pl-g2-six --uio /dev/uio0 move-six \
  --axis 1:<目标1>:500:10 --axis 2:<目标2>:500:10 \
  --axis 3:<目标3>:500:10 --axis 4:<目标4>:500:10 \
  --axis 5:<目标5>:500:10 --axis 6:<目标6>:500:10 \
  --observe-ms 5000 --execute
```

对 `standby → approach → grasp → lift → place → exit` 各跑一次，逐步记录
`target / last / target_error / fault` 与**实物结果**。

- `ERR` 只判定**当次命令**失败；操作者结合现场决定下一条显式命令。
- **不要用 shell 的 `&&` 串联六条命令**——那会让一个退出码无意间变成全流程禁动门禁。
  连续自动循环时用 PS 侧软状态机，故障进入任务策略，不设跨命令锁存。

### 常见坑

| 现象 | 原因与处理 |
| --- | --- |
| `limits` 读出 `1585–2500` | 板端还是旧镜像；新镜像上板前不要依据新范围（2050–3000）发命令 |
| 六轴 `move-six` 报 `fault=5 write_sent=0` | 描述符守卫拦下（限位/标定/禁发/截止时间/总线占用），逐项查 |
| 某轴不动 | 先查独立供电与接线；上电 `0x28=0`（卸力）——**不要靠加大 speed 去"顶"** |
| 夹爪报 `0x20` | 过载，如实记录；接触位置随工件尺寸变化，不是通用闭合 count |
| `calibrated_mask` 不是 `0x3f` | 有轴未标定，`move-six` 会直接拒答 |
