# G5：传送带动态抓取（预测拦截）

**状态：已跑通（2026-10-29）。** 13 轮 9 中（69%）、带速 69.9–86.6 mm/s 任意档位可抓，
详见 [evidence/g5-dynamic-20261029.md](../evidence/g5-dynamic-20261029.md) 与
[10.29 归档](10.29-归档与10.30任务.md)。入口是 [G3](3.G3-static-closed-loop.md) 的静抓闭环。

**阶段与节点（2026-10-19 定）**：

| 阶段 | 内容 | 节点 |
| --- | --- | --- |
| 5.1 | 停止-抓取（带上静止物体） | 可选，用于验证带面映射 |
| **5.2 伪动态** | 传送带匀速 + 物块固定起点 + **光电触发固定延时 T** 定点闭合 | **11-04 视频主体** |
| 5.3 真动态 | 提前量由**检测到的位置/速度**算，随物块状态变化 | 11-20 决赛 |

> **伪动态不是"作弊"**：它的价值论述是"用固定节拍把不确定性压到触发时刻"，这正是 PS-PL 分工要证明的东西。
> 视觉在 5.2 里负责检测与带面映射（视频与文档要用），抓取时机由光电开关给，稳定性远高于实时视觉触发。

## 核心策略：预测拦截，不是实时跟随

HX-30HM 总线舵机的节拍（约 200 count / 100 ms 量级，见 [G2 实测](2.G2-six-axis-calibration.md)的 20 样本 1008 ms）**不足以做"盯着移动物体实时跟随"**。因此本阶段采用的策略是：

> **在物体到达之前，把机械臂摆到拦截点等它。**

流程：检测物体 → 估计其速度与运动方向 → 预测"物体何时到达拦截点" → 在那个时刻把夹爪停在拦截点闭合。机械臂几乎不做长距离高速运动，而是**提前就位 + 时机对准**。

这带来一个重要的工程红利：**机械臂的运动时间被"提前量"吸收，系统的时间精度要求从"控制精度"降级为"触发时刻精度"**。

## 分级实施（逐级降险，不要跳级）

### 阶段 5.1：停止-抓取（stop-and-go）

- 传送带上物体静止 → 按 G4 的视觉引导流程抓走。
- 目的：证明"视觉 + 传送带工位"的坐标映射正确。
- 验收：连续 5 次静止物体在传送带上被抓。

### 阶段 5.2：单点拦截（伪动态，11-04 交付）

- 传送带以最低速运行，物体**单调匀速**通过，在传送带中段设一个固定拦截点。
- 物块从**固定起点**投放（挡边/导轨保证重复），触发方式优先用最简单可靠的：
  - **光电/接近开关**：物体到达上游检测点 → 延时 T 后闭合夹爪。**11-04 用这个。**
  - **视觉触发**：检测到物体进入上游参考线 → 记录时间 → 延时 T。（11-05 后升级）
- 延时 `T` 由实测标定：`T = (上游检测点到拦截点的距离) / 带速 − (夹爪闭合所需提前量)`。
- 验收：**慢速移动物体预测拦截 ≥3/5（目标 8/10）**，且 T 可用一条命令重标。

### 阶段 5.3：视觉测速 + 多位置拦截

- 用视觉连续两帧估计物体速度（`Δs/Δt`），或直接用编码器测带速。
- 拦截点可在传送带中段一段范围内选择（取"离物体当前位置最近的可用拦截点"）。
- 用 G6 的端到端延迟数据修正提前量。
- 验收：不同带速、不同初始位置下拦截成功率 ≥70%。

## 11-04 前做到真动态：把"拦截"拆成"提前就位 + 定时闭爪"（2026-10-20 定）

原计划 11-04 交伪动态、11-20 交真动态。**这个划分可以提前，因为真动态的瓶颈不是视觉，也不是算力，
而是"拦截动作的节拍"**——只要把它拆开，11-04 就能交真预测拦截。

### 瓶颈到底在哪

现状单轮抓放 **10.6 s**，其中每步 `move-six` 的最短观察期 1000 ms、最长 8000 ms，且要求"连续三轮全轴
进容差带"。用这条命令去拦截移动物块是不可能的：等它判完，物块早过去了。

但**"拦截"其实只包含一个新动作：闭合夹爪**。其余（走到拦截点、摆好姿态）都可以在物块到达之前
先做完。而单轴闭合实测 **757 ms** 就到位（10-20 测量）。

### 拆解后的时间线

```
t0            视觉/光电检测到物块进入参考线 → 记录 t0，算出飞行时间 T_flight
t0 + ε        机械臂从等待位出发，走向拦截点（2–3 s，物块还没到）
t0+T_flight-0.9 s  发单轴闭爪命令（ID6，实测 0.76 s 到位）
t0 + T_flight 物块到达拦截点，爪已闭合 → 抬升 → 送去放置位
```

**唯一硬约束**：`T_flight > 3.5 s`，也就是

```
检测线到拦截点的距离 / 带速 > 3.5 s
```

例：距离 200 mm、带速 40 mm/s → 5 s，够；带速 100 mm/s → 2 s，不够。**所以"真动态"要先限速**，
不是先把算法做快。这条决定了传送带的工作点，必须先测。

### 这样做的两个好处

1. **完全不动 `move-six` 的语义**：拦截只用现有单轴命令（`rtcs-pl-g2 move --id 6`），不需要改 RTL、
   不需要重综合、不需要动掩码那套判定；
2. **PS 侧只多一个定时器**：`检测时刻 + T_flight − 提前量`，Python 的 `sleep` 抖动量级 1 ms，
   远小于 0.76 s 的闭合余量。时间基准用 PL 的 `epoch_ms`（`diagnose` 已返回）对齐，避免跨进程漂移。

### "真动态"的诚实定义（11-04 用这个口径）

| 形态 | 触发 | T 怎么来 | 算不算真动态 |
| --- | --- | --- | --- |
| 伪动态 | 光电开关 | 固定值，标定一次 | 否（看起来像，本质是时机对准） |
| **视觉触发预测拦截** | **视觉：物块进参考线** | **实测距离 ÷ 实测带速 − 0.9 s** | **是（起点不固定也能抓）** |
| 真动态+ | 视觉两帧测速 | 每帧实时更新 T | 是（本质相同，鲁棒性更高） |

注意第二行的关键：**只要物块起点不固定、而 T 是由"检测时刻 + 实测带速 + 实测距离"算出来的，
就已经是真预测拦截**——起点变化被检测位置吸收了。多速度泛化是"真动态+"，11-04 不要求。

## 提前量的时间口径（2026-10-27 实测后定）

**唯一有效的量：从"触发时刻"到"爪真正接触物块"。** 其它口径都会系统性偏大。

2026-10-27 实测（静止工况，`static capture` 指令发出 → 夹住）：x = 300 mm 用 **3.16 s**、
x = 360 mm 用 **3.20 s**，差 40 ms（1.5%）。由此得两条：

1. **在 300–420 mm 区间内 `t_move` 与 x 基本无关**，一个常数足够，**不做 `t_move(x)` 表**；
2. 3.16 s **不能直接当提前量**——它含"稳定 0.5 s 才出点"（≈0.6 s），而动态触发是
   "越线的那一帧"，没有等稳定的过程。

拆开（与 10-26 的 13/13 分步数据一致）：

| 段 | 值 | 动态下是否计入 |
| --- | --- | --- |
| 视觉稳定判据 | ≈0.60 s | ❌ 不存在（越线即触发） |
| 串口 200 B @115200 | 0.02 s | ✅ |
| 板端起进程 + 载计划 + 校验 | ≈0.30 s | ✅（待实测） |
| approach + grasp 两段六轴 | ≈1.80 s | ✅（提前就位时不存在） |
| 闭爪到接触（全程 757 ms 的约 2/3） | ≈0.50 s | ✅ |

- **实时出发**（触发时才从 `exit` 位走向拦截点）：D ≈ **2.6 s**
- **提前就位**（臂已张爪守在拦截点）：D ≈ **0.8 s**

两者差 1.8 s，这就是"要不要提前就位"的全部价值。

### 怎么把 D 量准，不用秒表

`CLOCK_MONOTONIC` 在 PS 上跨进程是同一时钟，所以下面四行日志可以直接相减：

| 日志 | 含义 |
| --- | --- |
| `SERVER_ACCEPT mono_ms=` | 板端收到 JSON |
| `G3_T0 mono_ms=` | 子进程载完计划、准备动（差值 = 起进程+校验） |
| `G3_STEP name=... elapsed_ms=` | 每一步耗时 |
| `G3_STEP name=grasp.gripper ... position=` | 闭爪的观测位置 |

```
D_板端 = (G3_T0 − SERVER_ACCEPT) + Σ G3_STEP + 0.5 s(到接触)
D_总   = PC 侧判定耗时 + 串口传输 + D_板端
```

**闭爪那段不能直接取 `elapsed_ms`**：它含 `observe_ms=1200` 的观察窗口，而接触发生在
约 500 ms 处。用 `位置 - 目标 < 60` 判空/判接触（10-25 定），不要用耗时判。

## 类别分流：Cube 抓、Cylinder 放行（2026-10-27 定）

演示需要"认得出、分得开"：看到 Cube 抓，看到 Cylinder 放行。实现是
`capture_agent.py --class-name cube`：

- 只有 class 0 参与目标选择，Cylinder 不产生触发；
- 连续 4 帧"只有被排除的那一类" → 打印 `CAPTURE_PASS action=pass class=Cylinder`
  并**当场结束本次取点**（不听满 `--timeout`，否则演示时圆柱早走出画面）；
- 放行是**一条明确结论**，不是"没看见"：日志与 JSONL 用 `action=pass` 与
  `reason=timeout` 分开记，证据里才能统计"识别正确"与"根本没看见"。

⚠️ **前提**：10-15 记录过"cube/cylinder 混淆已实锤"。上线前必须在现场台面做一次混淆
检查（方块与圆柱各放一次、各跑 10 帧，看类名与 conf）。**混淆率高时不能把这个功能
写进报告的作用说明**，只能写"按类别选择抓取对象"。

**顺带修掉的一个洞**：`pick_target` 在带面内一个目标都没有时会退回"全体最高置信度"，
那一步原先没有最终检查。10-27 实测到 `conf=0.26 / y=150 mm` 的假目标（带宽只有 80 mm）
被当成有效点，喂给 `--grasp-xy` 后被插值两端夹住 → 臂去抓空气。现在中心落在标定带面
外的检测一律丢弃并计数（`CAPTURE_FAIL ... off_belt=N`），只告警、不抛错。

### 谁在什么时候做什么（2026-10-29 改为"踩着点出发"）

| 时刻 | 谁 | 动作 | 实现 |
| --- | --- | --- | --- |
| 每轮开始 | PC | 量带速/方向 → `config/g5_dynamic.json` | `g5_belt_profile.py` |
| 物块越检测线 | PC | 记 `t_frame`、当帧 `x`，算 `x_int / t_block / t_close / t_stage` | `g5_dynamic_trigger.py` |
| `t_stage` | PC | 发 `dynamic_stage`（臂从 exit 高位**扑向这次算出来的 x_int**） | 同上 |
| +1.95 s | PS | 臂到位、夹爪保持张开，进程退出 | `g3_station_runner.py --stop-after grasp` |
| `t_close` | PC | 发 `dynamic_close` | 同上 |
| +0.5 s | 舵机 | 爪接触物块（此刻物块正好到 `x_int`） | — |
| +6 s | PS | lift/place/retreat/exit 跑完，回 exit 位 | `g3_station_runner.py --resume close` |

**为什么不提前就位**：10-29 实测"先守在那儿"只有 x 固定、y 必须完全对得上才夹得住，
而且观感像"等在那儿合爪"。改成踩着点出发后，臂的动作与静态抓取完全一致（到物块所在处
再闭爪），x 由插值给出、每次不同；提前量只是把"什么时候出发"算出来。

### 时刻怎么算

```
x_int   = 物块当前位置 + v × (advance + move + margin)   ，夹在窗口 [350, 390] 内
t_block = 物块中心到达 x_int 的时刻
t_close = t_block − advance          （advance ≈ 0.30 s：命令→咬合）
t_stage = t_close − move − margin    （臂出发的时刻）
```

**臂一报到位就立刻闭爪（2026-10-29 定）**：不再 `sleep` 到 `t_close`。原先是按
`move` 估出来的墙上时刻等，`move` 估 1.95 s、实测 2.0 s，这点误差全变成"臂到位后愣
0.3~0.5 s"；现在提前量只有 0.3 s，这点干等正好把物块放过去。改成"跟着臂的到位回包走"
之后，臂慢一点、快一点都自己跟上了，`stage_margin_ms` 只当微调。
到位偏早/偏晚超过 150 ms 时日志会打 `G5_WARN 臂到位比计划…`，按那个数改 `move_to_pose_ms`。

**带速在视野里现估（2026-10-29 加）**：物块从检测线走到拦截点有 2~3 s、二十几帧，
`estimate_speed()` 用最近 12 帧做最小二乘，越线那一刻直接拿这个速度算 `x_int / t_block`，
不再信开机时量一次的常数（档位一改、带子一热就变了）。样本不足 4 帧或跨度 <0.3 s 时
退回配置值并打 `G5_INFO`；与配置差超过 35% 打 `G5_WARN`。实测噪声 ±0.6 mm 下，
12 帧拟合误差 0.4%（66.90 vs 67.14）。

`move` = 发 `dynamic_stage` → 臂到位，**实测 1936 / 1953 ms**（2026-10-29，x=370，
从 exit 高位出发）。臂不在 exit 时这个数不成立（复位后首动 4.2 s），所以每轮结束必须回 exit。

**由此反推检测线位置**：`检测线 ≤ 窗口下沿 − v×(advance+move+margin)`。
v=67.14 时 = 350 − 187.6 = **162 mm**；当前检测线 120 mm，余量 42 mm。
带速再高就得把检测线前移，否则 `stage_in < 0`，臂一定晚到。

### 闭爪必须走 C 单轴命令（2026-10-29 定）

`arm_ms − cycle_ms` 是"起一个 runner 进程要多久"，7 次实测 **861 / 876 / 877 / 877 /
879 / 881 / 882 ms**——非常稳定，也就是说**每条命令发出后要白等 0.88 s 舵机才会动**。
在 67 mm/s 下这 0.88 s 等于物块走 **59 mm**，正好是"从虎口走过去"。

所以闭爪不再经过 runner：

| 路径 | 命令 → 舵机开始动 | 命令 → 咬合物块 |
| --- | --- | --- |
| 旧：runner `--resume close` | ~880 ms | ~1.38 s |
| **新：server 直接调 `rtcs-pl-g2`（C）** | ~50 ms | **~0.27 s** |

那 880 ms 被挪到"已经夹住之后"（lift/place 才开始跑），不再吃掉抓取时机。
runner 相应地多了一个 `--resume lift --grip-hold N`：跳过闭爪、直接用快路径读到的接触位置。

配套把闭爪速度从 800 提到 **1500**（`speed_raw_max` 上限），全程 757 ms → 约 404 ms，
接触从 ~500 ms 提前到 ~210 ms。

**`observe_ms` 下限是 1000**（`rtcs-pl-g2` 只接受 1000..10000、且必须是 100 的倍数）。
2026-10-29 踩过：写 600 被 C 命令直接判参数错误，**一条帧都没发出去**，表现是
`grip=fault`、位置读回等于命令目标，然后 `lift` 多轴联动把物块扫下带。
server 现在会把低于下限的值抬到 1000 并打 `SERVER_WARN`，失败时还会打 `RAW_CLOSE` 原始输出。

### 常驻模式（2026-10-29 改）

`capture_agent.py` 和 `g5_dynamic_trigger.py` 默认都是**一直跑**，按 `q` 退出：

| 脚本 | 常驻行为 | 防重抓的方式 |
| --- | --- | --- |
| `capture_agent.py` | 抓完**立刻**按 x 从大到小抓下一件 | **位置去重**：同一位置（±`--dup-mm 8`）在 `--retry-after-s 3` 秒内不重复下发 |
| `g5_dynamic_trigger.py --loop` | 每轮自成一体（stage→close→搬运→exit） | 下一件从检测线上游进来才会武装 |

**为什么静态不用"等场景清空"**：传送带上常常同时有多件，要求清空永远不成立——
10-29 踩过，日志打"场景 20 s 没清空"然后死等。现在改成按位置去重：
不同位置立刻抓（多件按 x 从大到小依次抓），同一位置要等 `--retry-after-s` 秒才重试，
夹空不会变成原地死循环。机械臂还没复位时新放上去的件，复位后立刻就会按顺序抓。

`--once` / `--cycles N` 仍保留，验收统计要用（分母含失败，不许重试顶替）。
键盘用 `msvcrt` 非阻塞轮询，**q 只在本轮之间生效，不打断正在跑的动作**。

### 多条目标时抓哪一件

黄框（标定带面四边形）内取 **x 最大**的那一件——它最先到拦截点。规则在
`grasp_point.pick_target`，静态与动态共用；动态侧再叠一条候选条件：必须还在拦截窗口
上游 `min_upstream_mm`（默认 30 mm）以外。

### 两个反向失败怎么读日志

| 日志 | 形态 | 下一步 |
| --- | --- | --- |
| `grip=empty`，`x_trig` 正常 | 爪合到底没碰着 = **太晚** | advance −50 ms（或窗口上移） |
| `grip=empty`，物块被顶回/撞翻 | 爪先合上了 = **太早** | advance ＋50 ms |
| `G5_WARN 来不及 (stage_in=负)` | 物块进视野时已离窗口太近 | 检测线前移，或降带速 |
| `G5_WARN 物块已在检测线下游，未武装` | 起点在线上游之外 | 把它放到 x≈100 再开带 |

### ⚠️ 关于日志里的 y（2026-10-29 澄清，已关闭）

示教表 6 个点全 `y_mm=36`（`same_lane=yes` → **插值只沿 x**），所以物块在带上的 y
必须落在夹爪容差内。但日志里出现的 `y=55` 一类数值**不是夹取位置真的偏**：相机把
夹爪识别成了 ID5 舵机，测到的中心因此偏出 20 mm 左右。

**处置：不要拿日志里的 y 当判据。** 如果实际夹取位置确实偏，由操作者手动挪底座解决。
早期一版文档把它当成"标定失效"来追，是错的，已改。

先按顺序排除：① `grasp_point.py --frames 3 --json` 看有没有 `belt_quad_mismatch iou<0.5`
→ 有就重标（`belt_calibration_dynamic.py`）；② 再考虑加挡边/导轨把物块约束到固定车道。
**不要用代码去补 y**：表里没有这一维，硬补就是猜。

## 硬件与接口需求

| 项 | 说明 |
| --- | --- |
| 传送带 | 电机驱动，速度可调；**必须先能手动调速并测出带速** |
| 触发信号 | 光电开关或接近开关接到 PS 的 GPIO/UIO（或先用视觉触发，避免改 PL） |
| 带速 | 需实测（输送带周长 × 转速，或用标记物计时） |
| 拦截点 | 在传送带工作段内选定，需在机械臂可达范围内 |

> **不改 PL 的红线**：优先用视觉触发或 PS 侧 GPIO，避免为传送带新增 PL 通路。若必须新增触发输入，按 `skill/zynq-6dof-rtcs/SKILL.md` 的 AXI 外设流程走，并升 ABI。

## 需要记录的数据（G6 统计的输入）

每次拦截试验记录：
- 物体真实轨迹或可核查测量、图像帧时间戳
- 检测完成时间、坐标变换完成时间
- 六轴命令提交与发帧时间、最后有效反馈时间
- **物体实际是否被抓住**（目视）、命令截止时间、故障码与恢复动作
- 命中/未命中

时间戳须注明时钟域或同步换算依据；无效反馈用 `UNAVAILABLE`；**失败试验保留在分母中**。

## G5 验收标准

| 级别 | 标准 | 节点 |
| --- | --- | --- |
| 最低 | 静止物体在传送带上被抓 ≥5 次（阶段 5.1） | 可选 |
| **交付线** | **伪动态：固定 T 定点拦截 ≥8/10**（阶段 5.2） | **11-04** |
| 目标 | **真动态：视觉提前量、两种带速下 ≥3/5**（阶段 5.3） | 11-15 |
| 理想 | 多速度下拦截成功率 ≥70%，端到端延迟 < 1.5 s | 11-20 |

## 阶段边界

- 传送带与触发逻辑属于 PS 侧任务策略；**PL 的限位、截止时间与急停职责不变**。
- 拦截失败时物体继续前进，必须保证**机械臂不追击**（避免超出工作空间或撞到传送带）。
