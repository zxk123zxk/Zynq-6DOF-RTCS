# 1. G1：单舵机协议与物理层

## 既有 USB 路径验证（2026-09-29）

AX7Z020B 已从 SD 启动 PetaLinux；1 GiB DDR、SD、PS 串口及 PL 寄存器 ID 0x52540001 已验证。BusLinker V3.0 枚举为 1a86:55d3（CH343），内核 CONFIG_USB_ACM=y，设备为 /dev/ttyACM0；没有 /dev/ttyUSB* 是正常的。

在 1 Mbps、8N1、无流控下，ID 1–6 各自单播 PING 和读取当前位置均返回 servo_error=0x00、RTCS_BUSLINKER_G1_OK。本次位置原始值依次为 2220、868、3088、2868、2061、1582；这是当时读数，并非关节标定角。断开舵机总线、保持 BusLinker USB 在线后，ID 1 PING 返回预期的 ERR response_timeout，且没有成功标志。这是历史 USB 只读基线，不在本轮重复测试。

## PL 直连 G1：已通过（旧接线 ABI 0x52540002）

用户确认本次实物测试使用的是归档中的 SD 镜像。UIO 为 `rtcs / 0x43c00000 / 0x00010000`；`probe` 显示 `0x52540002`，J20-33↔38 未装/装上分别为 `physical_tx=DISABLED/ENABLED`；ID 1 单播 PING 与 READ 成功，位置原始值为 `2038`；BusLinker 保持工作、仅断开 ID 1 舵机总线后，PING 和 READ 均返回 `ERR pl_fault=3`。完整镜像哈希与证据边界见 [G1 旧镜像归档](../artifacts/archive/g1-u20-inhibit-abi02-20261005/MANIFEST.md)。没有电压仪器实测数值和独立供电切断后的实测记录，不将电路设计值冒充测量结果；G1 通过不授权 G2 运动。

## 当前源码与只读边界

`src/pl/rtl/hx30hm_g1_engine.sv` 只接受 ID 1–253 的 PING/当前位置 READ；`src/pl/rtl/uart_byte_tx.sv` 和 `src/pl/rtl/uart_byte_rx.sv` 使用 100 MHz 时钟实现 1 Mbps 8N1。回复检查 ID、长度、停止位、校验和、舵机错误及超时。`sim/run_hx30hm_g1_engine.ps1` 在不接舵机时完成自检。

新 J20 接线工程将 ABI 升为 `0x52540003`，基址仍为 `0x43C00000`。寄存器偏移：`G1_ID=0x50`、`G1_OP=0x54`（1=PING，2=READ）、`G1_CMD=0x58`（完整字写 1=启动、2=清除）、`G1_STATUS=0x5c`（bit0忙、bit1完成、bit2故障、bit3物理禁发）、`G1_RESULT=0x60`（bit15:0位置、bit23:16舵机错误）、`G1_FAULT=0x64`。故障码 0=正常、1=非法ID、2=非法操作、3=超时、4=长度、5=停止位、6=应答ID、7=校验、8=舵机错误。旧新镜像接线不兼容，CLI 必须在任何命令写入前核对 ABI。

构建脚本默认选 `rtcs_axi_wrapper_bd.v` 无外部舵机引脚的安全版；加 `-Ttl` 时选 `rtcs_axi_wrapper_ttl_bd.v`。新接线用 V15/U20 导出 TTL TX/RX，W15 是上拉禁发输入，J20-36/W15 接 J20-38/GND 后才允许单播只读发帧。`probe` 显示禁发状态；旧 ABI `0x52540001/0x52540002` 均不得与新 CLI 混用。

## TTL 接线与实物验收

AX7Z020B J20 与 BusLinker TTL 排针均为公针，使用三根 2.54 mm 母对母线：J20-33/U20/Bank34 RX ← BusLinker TX；J20-35/V15/Bank34 TX → BusLinker RX；J20-37 GND ↔ GND。另用一根线只在 J20-36/W15 与 J20-38/GND 之间作允许跳线。不连接 J20 的 5 V/3.3 V。BusLinker 由独立 5–14 V 电源供电；断电后把两只跳帽置于 Servo–TTL，不把 Type-C 接 Zynq USB Host；PS UART1 调试串口仍可接电脑。

BusLinker 原理图中外部 TTL 的回传由 +3.3 V 的 U5 输出，舵机侧发送由 +3.3 V 的 U4 驱动并有钳位；这是电路设计依据，不是电压实测。新镜像的 SD 更新和无 BusLinker `probe` 步骤见 [SD 启动说明](SD启动与项目迭代操作说明.md)。

## 新接线镜像的实物边界

本轮只要求新镜像在**不接 BusLinker**时完成 ABI `0x52540003` 与 J20-36↔38 禁发状态的 `probe`；旧 G1 通信结果已归档，不复测 USB、DDR 或六只舵机。不发送 WRITE 或任何运动指令。G2 真实标定与实物动作另行验收、另行授权。
