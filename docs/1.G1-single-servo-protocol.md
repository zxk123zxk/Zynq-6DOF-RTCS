# 1. G1：单舵机协议与物理层（已通过）

本阶段证明 PL 能在 1 Mbps 半双工总线上与单颗 HX-30HM 通信，并把"能否发帧"交给一个物理禁发跳线控制。**已通过。**

## 当前 G1 契约（ABI `0x5254000E`）

基址 `0x43C00000`。G1 寄存器：`G1_ID=0x50`、`G1_OP=0x54`（1 PING，2 READ 当前位置，9 TORQUE_OFF，11 READ 扭矩开关 `0x28` 一字节）、`G1_CMD=0x58`（完整字写 1 启动、2 清除）、`G1_STATUS=0x5c`（bit0 忙、bit1 完成、bit2 错误、bit3 物理禁发）、`G1_RESULT=0x60`（bit15:0 位置或低字节扭矩值、bit23:16 舵机错误）、`G1_FAULT=0x64`。

故障码：0 正常、1 非法ID、2 非法操作、3 超时、4 长度、5 停止位、6 应答ID、7 校验、8 舵机错误、**13 该操作码不允许走 G1 路径**。

`uart_byte_tx.sv`、`uart_byte_rx.sv` 用 100 MHz 时钟实现 1 Mbps 8N1。共享引擎另有 G2 内部的原子 `OP_TORQUE_MOVE`（`0x28..0x2F` 8 字节块）与 `OP_TORQUE_OFF`（`0x28<-0`）。

**关键边界：`rtcs_top` 的 G1 白名单为 {PING, READ 位置, READ 扭矩, TORQUE_OFF}。任何能写位置的操作码经 G1 提交时，PL 只报 `fault=13` 且不发字节**——即 G1 路径结构性地无法产生运动。单播 ACK 只证明协议层接收，不证明机械到位。

## 扭矩开关：上电默认卸力（重要）

HX-30HM 的 `0x28` 是 SRAM 扭矩开关，**上电初值 0 = 卸力**。这是 ABI 07 定因出来的结论，也是每次断电重启后必须记住的前提：**不给 `0x28=1`，舵机不会动**。当前实现把 `0x28=1` 与目标位置合并进同一条原子 WRITE（`OP_TORQUE_MOVE`），并提供只写 `0x28<-0` 的 `release` 卸力子命令。`0x28` 写 `128` 会把当前位置标定为 `2048`，本路径只用 `1`/`0`。

2026-10-12 板端 `torque-status --id 5` 读回 `value=0`，与该结论一致（断电后 SRAM 复位）。

## TTL 接线

J20 与 BusLinker TTL 排针均为公针，使用母对母 2.54 mm 线：

| PL 侧 | 接到 |
| --- | --- |
| J20-35 / V15（PL RX，输入） | BusLinker 丝印 TX |
| J20-33 / U20（PL 三态 TX，输出） | BusLinker 丝印 RX |
| J20-37 | GND |
| J20-36 / W15（禁发输入） | 跳线到 J20-38 / GND 才允许发帧 |

无跳线禁发，运行中拆除立即中止；不接 J20 电源脚。BusLinker 跳帽置 `Servo–TTL`，舵机由独立 5–14 V 供电。原理图的 3.3 V 逻辑供电与钳位是设计依据，不是现场电压测量。
