# 1. G1：单舵机协议与物理层

## 已有实物验收

2026-09-29 USB/CH343 基线：BusLinker `1a86:55d3` 绑定 `CONFIG_USB_ACM=y`，出现 `/dev/ttyACM0`；ID 1–6 单播 PING 和 READ 成功，当时位置分别为 2220、868、3088、2868、2061、1582。断开舵机总线且 BusLinker USB 在线，ID 1 PING 按预期超时。上述数字不是关节标定值。

PL 直连 G1 已通过：ABI `0x52540002` 下 UIO=`rtcs / 0x43c00000 / 0x00010000`，旧 J20-33↔38 禁发跳线使 `physical_tx` 从 `DISABLED` 变 `ENABLED`；ID 1 PING、READ（当次 2038）成功；断开 ID 1 舵机总线时 PING/READ 均为 `ERR pl_fault=3`。见 [ABI 02 归档](../artifacts/archive/g1-u20-inhibit-abi02-20261005/MANIFEST.md)。迁针 ABI `0x52540003` 下 J20-36↔38 禁发跳线及 ID 1 PING/READ（当次 1995）亦由用户上板确认，见 [ABI 03 归档](../artifacts/archive/g1-v15-inhibit-abi03-20261006/MANIFEST.md)。无 `sudo` 打开 `/dev/uio0` 报权限不足。Bank34 电压及独立电源开关切断效果无仪器实测记录，不填造数值。

## 当前源码契约

当前版本已升至 ABI `0x5254000C`；下文 ABI 07 的一次性锁描述仅供历史对照。ABI 12 的单轴限位、现场起点和反馈判定见 [寄存器契约](g2-abi12-registers.md)。

当前 RTL/CLI ABI 为 `0x5254000C`，基址 `0x43C00000`；旧 CLI 与新 bitstream 不可混用。G1：`G1_ID=0x50`、`G1_OP=0x54`（1 PING，2 READ 当前位置，9 TORQUE_OFF，11 READ 扭矩开关 `0x28` 一字节）、`G1_CMD=0x58`（完整字写 1 启动、2 清除）、`G1_STATUS=0x5c`（bit0忙、bit1完成、bit2错误、bit3物理禁发）、`G1_RESULT=0x60`（bit15:0位置或低字节扭矩值、bit23:16舵机错误）、`G1_FAULT=0x64`。故障码 0 正常、1 非法ID、2 非法操作、3 超时、4 长度、5 停止位、6 应答ID、7 校验、8 舵机错误、**13 该操作码不允许走 G1 路径**。

`uart_byte_tx.sv`、`uart_byte_rx.sv` 用 100 MHz 时钟实现 1 Mbps 8N1。共享引擎还有 G2 内部单播的原子扭矩+目标 `OP_TORQUE_MOVE`（`0x28..0x2F` 8 字节块）与 `OP_TORQUE_OFF`（`0x28<-0`）。**`rtcs_top` 的 G1 白名单为 {PING, READ 位置, READ 扭矩, TORQUE_OFF}：任何能写位置的操作码经 G1 提交时，PL 只报 `fault=13` 且不发字节**。默认安全 wrapper 不导出物理舵机端口；`scripts/build_vivado.ps1 -Build -Ttl` 才使用 TTL wrapper。单播 ACK 证明协议层接收，不证明机械到位；位置反馈与扭矩读数需分别记录。

## TTL 接线

J20 与 BusLinker TTL 排针均为公针，使用母对母 2.54 mm 线。ABI 06 改为 **J20-35/V15（PL RX）← BusLinker 丝印 TX；J20-33/U20（PL 三态 TX）→ BusLinker 丝印 RX；J20-37 GND ↔ GND**。旧 ABI 03–05 已成功通信的接法方向相反，不能沿用旧镜像或旧接线。另将 J20-36/W15 上拉禁发输入与 J20-38/GND 用单独跳线接通才允许发帧。无跳线禁发，运行中拆除立即中止；不接 J20 电源脚。BusLinker 跳帽置 `Servo–TTL`，舵机由独立 5–14 V 供电；Type-C 不参与 PL 直连，PS UART1 调试串口仍可接电脑。

BusLinker 原理图存在 `EX_TX/EX_RX` 网络名；接线以实物丝印和本 ABI 的 PL 方向为准。ABI 06 XDC 将 U20 设为输出、V15 设为输入。原理图的 3.3 V 逻辑供电与钳位是设计依据，不是现场电压测量。

ABI 04 的首次实物试动在原 2 秒期限内 `fault=9`、末次反馈1999，稍后 READ 为2006；不是 G2 通过。原文件见 [ABI 04 归档](../artifacts/archive/g2-id1-abi04-20261006/MANIFEST.md)。ABI 05 上板预读2006后拒绝且未发 WRITE，见 [ABI 05 归档](../artifacts/archive/g2-id1-abi05-20261006/MANIFEST.md)。ABI 06 继续区分准时、迟到与超时，不自动重发 WRITE。

ABI 06 已上板：ABI、禁发、一次性状态与预读 `2005` 全部通过，WRITE 帧 `FF FF 01 09 03 2A CE 07 00 00 32 00 C1` 已发出且被舵机应答 `ERROR=0`，但 5 s 观察期内 99 次反馈仍为 `2005`、无可见运动，报 `fault=9`、`write_sent=1`（一次性锁已消耗）。即协议/接线/帧编码已被证明正确，故障点在舵机执行条件；定因读表、判定树见 [ABI 06 故障判定](g2-id1-abi06-fault9-诊断与判定方案.md)。

**ABI 07 定因结论**：出厂寄存器表（HX-30HM V3.7 / 固件 2.43）显示 `0x28` 扭矩开关为 SRAM、上电初值 **0 = 卸力**；用户把舵机总线拔掉后可自由转动，反证电气/机械无问题，缺的就是 `0x28` 未写 1。ABI 07 据此把 `0x28=1` 与目标位置合并进同一条原子 WRITE（`OP_TORQUE_MOVE`），删除只写 `0x2A` 的位置专用帧，并新增只写 `0x28<-0` 的 `release` 卸力子命令（不写位置、不消耗一次性机会）。`0x28` 写 `128` 会把当前位置标定为 `2048`，本路径只用 `1`/`0`。实施与契约见 [ABI 07 实施记录](g2-id1-abi07-implementation.md)。
