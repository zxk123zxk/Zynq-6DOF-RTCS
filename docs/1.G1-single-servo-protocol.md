# 1. G1：单舵机协议与物理层

## 当前结论（2026-09-29）

AX7Z020B 已从 SD 启动 PetaLinux；1 GiB DDR、SD、PS 串口及 PL 寄存器 ID 0x52540001 已验证。BusLinker V3.0 枚举为 1a86:55d3（CH343），内核 CONFIG_USB_ACM=y，设备为 /dev/ttyACM0；没有 /dev/ttyUSB* 是正常的。

在 1 Mbps、8N1、无流控下，ID 1–6 各自单播 PING 和读取当前位置均返回 servo_error=0x00、RTCS_BUSLINKER_G1_OK。本次位置原始值依次为 2220、868、3088、2868、2061、1582；这是当时读数，并非关节标定角。断开舵机总线、保持 BusLinker USB 在线后，ID 1 PING 返回预期的 ERR response_timeout，且没有成功标志。**PS Linux → USB → BusLinker → 六舵机的只读通信及断线超时已通过；PL 直连仍未完成。**

## 剩余留证与 PL 直连实现

1. **USB 留证：**保存本次 12 次成功应答和一次断线超时的串口日志；用逻辑分析仪分别记录 PING、READ 请求和回复，核对 1 µs 位宽、8N1、ID、ERROR 与校验和；补存电源/共地/急停接线、构建日志及 artifacts/sd/SHA256SUMS。断线超时已通过；坏帧、错误校验及急停抑制尚未验证。
2. **PL 硬件前置：**确认外部半双工收发器型号、电平、方向真值表、AX7Z020B 引脚与 Bank、共地、总线供电和独立硬件急停。未确认前不添加猜测的 XDC 引脚，也不把 PL IO 直接接 5 V 舵机总线。
3. **PL 实现：**在 src/pl/rtl/servo_bus_master.sv 的只接收观察器上增加 100 MHz 时钟下的 1 Mbps UART 发送、仅 PING/READ 的帧生成、回复解析/校验/超时及 TX→RX 高阻切换；将 src/pl/rtl/safety_monitor.sv 的急停、看门狗、故障锁存接入发送许可。扩展 AXI 命令/状态寄存器及 Linux UIO 只读 CLI，确保其他指令码、广播 ID 和故障状态不能使能发送。先做仿真和独立电气验证，再导出真实 IO、更新 XSA/镜像，最后用逻辑分析仪和隔离舵机实测。当前 src/pl/rtl/rtcs_axi_wrapper_bd.v 将 servo_rx、estop_n 固定为高，servo_tx_en 固定为零；BusLinker 成功不能作为 PL 直连验收。

**阶段判定：**USB 只读功能及断线超时通过；USB 波形/证据、其余故障路径和 PL 直连待完成。G1 不进行机械臂运动。
