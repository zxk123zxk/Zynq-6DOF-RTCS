# Hardware bring-up master plan（硬件上板总规划）

本文件只保留跨阶段的安全门禁和阶段入口。每个阶段的核心改动、验收产物和边界分别记录在 `0.G0-ps-pl-foundation.md` 至 `4.G4-dynamic-demo.md`，避免同一事项在多份文档中重复维护。

| 阶段 | 当前状态 | 开始条件 | 完成的最小证据 |
| --- | --- | --- | --- |
| G0 | 已完成 | 板卡与基础供电可核验 | PS7/AXI 工程、寄存器仿真、Linux 启动和 G0 电气/急停记录 |
| G1 | 未开始 | 单舵机隔离、方向控制与硬件急停可验证 | 单舵机 PING/READ 波形、校验和、超时/断线故障记录 |
| G2 | 未开始 | G1 通过且六轴实测标定完整 | 六轴标定表、低速受限同步写与限位拒绝记录 |
| G3 | 未开始 | G2 通过 | RTL 回归、100 次静态抓放、反馈/安全故障记录 |
| G4 | 未开始 | G3 通过 | 动态目标、截止命中率、P99 抖动和最终演示记录 |

## 始终有效的安全规则

- 舵机使用独立、实测的电源；不得从 Zynq GPIO 电源轨供电。
- 所有舵机总线连接前必须确认共地、PL Bank 电压、收发器逻辑电平和高阻释放时序。
- 硬件急停必须独立于 Linux、PS、PL 软件路径，能够物理阻止执行动作。
- 未通过对应阶段的实测证据前，`servo_tx_en` 必须保持禁用。
- 所有关节 ID、零位、方向、限位和性能数据必须来自实测；禁止补写或猜测。
- 每阶段只在验收产物已保存且可复查后才进入下一阶段。
