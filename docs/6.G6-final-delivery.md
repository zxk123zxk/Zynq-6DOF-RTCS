# G6：稳定性、性能度量与决赛交付

**状态：未开始。** 入口是 [G5](5.G5-conveyor-dynamic.md) 的预测拦截跑通。本阶段不新增功能，只做**稳定性、数据与交付**。

> **本阶段是流程门禁（[归档轨](0.1hardware_bringup.md)）真正需要的时间窗。** 前面阶段跳过的统计与归档，在这里补齐——它们是为答辩和作品文档服务的，不是运动的前置条件。

## 目标

1. 把动态抓取从"能跑通"变成"能连续稳定跑"。
2. 产出可写进作品文档与答辩 PPT 的**量化数据**。
3. 完成决赛现场演示的准备（含降级预案）。

## 工作项

### 6.1 稳定性与成功率统计

- 在固定带速、固定负载、固定工位下连续运行 **≥20 次**，记录每次成功/失败。
- 统计：总次数、成功数、成功率、平均单次节拍、连续成功的最长串。
- 任一失败结束当前批次并记录恢复动作；**不把失败计作成功，也不从分母里剔除**。
- 目标：成功率 ≥80%。

### 6.2 端到端延迟与抖动

- 测量并记录：图像采集时间戳 → 检测完成 → 坐标变换/位姿生成 → PL 命令提交 → 发帧 → 六轴最后有效反馈。
- 给出样本数、均值、P50、P95、**P99**。
- **PS/PL 分工对比（这条是答辩加分项，也是本工程的核心论点）**：
  - 建立 **Linux-only 基线**（全部在 PS 做，PL 只做透传）与 **PS-PL 分工**两组对照；
  - 两组使用同一目标速度、负载、工位和成功判据，记录各自软件/PL 版本；
  - 对比端到端延迟、P99 抖动与截止时间命中率。
  - 这就是"为什么要把时序关键逻辑放进 PL"的**实测证据**，比任何描述都有说服力。

### 6.3 故障注入与恢复

- 单列测试：舵机 ERROR、丢反馈、截止时间超期、视觉丢帧、软件 `stop`、独立断电急停。
- 对每一项记录触发条件、系统行为、恢复动作与耗时。
- **不把独立断电急停的功劳归给视觉或软件**。

### 6.4 长跑

- 连续运行 **≥30 分钟**（或 ≥200 次循环），记录成功率漂移、温度（`0x3F`）、电压（`0x3E`）、电流（`0x45`）。
- 目的：暴露热漂移、电源压降、机械松动等只在长跑中出现的退化。

### 6.5 交付材料

- 作品文档：架构（PS-PL 分工）、安全设计（红线门禁）、标定与视觉、动态抓取策略、**实测数据**。
- 演示视频：完整流程，含一次失败与恢复（真实比完美更可信）。
- 答辩 PPT：突出"**异构分工的量化收益**"与"**平面视觉 + 预测拦截**的工程取舍"。
- 现场预案：相机失效或视觉不稳 → G3 固定工位抓取；传送带故障 → 静止物体抓取。**每一级都要提前录制视频备播。**

## G6 验收标准

| 项 | 标准 |
| --- | --- |
| 连续次数 | ≥20 次，成功率 ≥80% |
| 长跑 | ≥30 min 无不可恢复故障 |
| 数据 | 端到端延迟分布 + P99 + PS/PL 对照 |
| 材料 | 文档、视频、PPT、三级备播视频全部就绪 |

## 阶段边界

- 本阶段**只做度量与交付，不新增功能**。任何新功能若会威胁稳定性，一律推迟到赛后。
- 统计口径一旦确定就不再修改；发现口径错误时必须**重跑**而不是"按新口径重算旧数据"。
