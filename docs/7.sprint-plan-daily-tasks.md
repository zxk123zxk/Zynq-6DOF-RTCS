## 每周节奏（固定下来）

```
周一 定本周验收物 + 30 min 站会（同步三人的阻塞点）
周二~四 开发；每日 15 min 同步
周五 "能跑起来给人看"的验收：必须跑一遍全链路并录屏
周六 证据归档 + 补文档（归档轨；竞赛轨的门禁在此补齐）
周日 休息 / 处理意外
```

**每周必须有一个"能演示的东西"**——不是"完成了 80% 的代码"，而是一条能跑起来的链路。

## 明确"跳过"清单（保护工期）

以下事项在本轮冲刺中**明确不做**，做了就是浪费工期：

| 跳过项 | 理由 |
| --- | --- |
| 训练任何深度学习模型（含 GraspNet/Graspness） | 无深度相机、无 GPU、39 天不可能；见 [G4](4.G4-static-vision-grasp.md) |
| 引入 ROS / MoveIt / Gazebo | 与现有 UIO + 裸 RTL 通路冲突，rootfs 也装不下 |
| 6 自由度解析逆运动学 | 5 关节 + 平面抓取，示教表 + 插值足够 |
| 完整 3D 手眼标定 | 平面抓取只需平面映射 |
| **棋盘格/标定板与相机内参标定** | 2026-10-13 实测角点检出不稳、误检严重；背景已固定为黄桌面/绿传送带，**平面上的实测点对会把畸变一起吸收**，不需要独立内参，见 [G4](4.G4-static-vision-grasp.md) |
| 通用背景鲁棒性（换桌布、换颜色、杂乱背景） | 背景已固定为两种工况；为其它背景调参不产生验收价值 |
| 100 次静态循环全量记录、逐条证据引用 | 归档轨事项，**不是运动前置条件** |
| 为竞赛轨填 `g3_station_plan.json` / `g3_observation_log.json` | 同上；需要时周末补 |
| `trajectory_engine.sv` / PL 侧 FIFO / 硬件 IRQ | PS 侧软状态机即可；无实测需求就不动 PL |
| DMA / HLS 加速 | 视觉是低频（每次抓取一帧），无带宽压力 |
| 动态"实时跟随" | 舵机节拍不允许，改预测拦截；见 [G5](5.G5-conveyor-dynamic.md) |
| 无人值守通宵跑 | 红线：运动期间必须有人在场 |

## 三条不可让的价值排序

当工期冲突时，按此顺序砍功能，**不砍红线**：

1. **保 11.04 的静态抓取交付**（W2 的兜底视频是绝对底线）
2. **保 11.20 的演示可用性**（宁可成功率 70% 能稳定演示，不要 90% 但会死机）
3. **保数据与文档**（答辩分数的来源）

→ 具体降级路径：视觉没成 → 用盲抓视频；传送带没成 → 静态抓取演示；多速度没成 → 单速度演示。
