## 结论先行

- **今天打通了**：新 bitstream/SD 镜像、限位三处副本一致、夹爪拆分、夹持段逐轴搬运、
  六步状态机全链路（standby → place 全部 OK，夹住物块完成搬运与放置）。
- **唯一没打通**：`exit` 回程。ID2 从放置侧（2433）回抓取位（2060）卡住，`fault=9 fault_id=2`。
- **根因是机械/运动学，不是软件**：ID2 在约 2040–2070 存在随姿态漂移的"过中心"死区；
  卡住时 `servo_error_raw=UNAVAILABLE`、`engine_fault=0`，没有过载，不是扭矩不足、不是门禁。
- **明天的解法**：在"抓取↔放置"和"放置↔复位"之间各加一个**中间抬高位**，用抬高位绕开死区。
- **11.04 的"静态抓取 + 假动态"目标可行但紧**，关键路径是机械位点闭环，不是视觉。

## 系统当前能力边界

**能**：
- 单轴 / 六轴同步 / 逐轴搬运任意位点；
- 夹爪开合，过载判定为"夹住"，张开失败才判故障；
- 六步状态机顺序执行、单步故障留痕、失败回退；
- 夹住物块完成 grasp → place → 张开（实测通过）。

**不能**：
- 从放置侧自动回到抓取侧（ID2 死区）；
- 连续多轮（回程不通）；
- 夹持段逐轴搬运的中间姿态未经碰撞校验。

## 明天的最小目标

   抬高位的判据是"ID2 跨死区时末端有足够余量、不扫传送带"。
2. 让所有位点落在死区同一侧，或由抬高位负责跨侧，避免六轴命令直接穿死区。
3. 跑通 `--once` → `--loop 3`。

## 11.04 进度评估

**剩余 16 天**（10.19 → 11.04）。硬节点：静态抓取作品文档 + 视频。

当前状态：六步链路 7/8 步通，缺回程；连续 3 次未达成。

"假动态"（传送带 + 物块移动提前量）的四个前提：

| 前提 | 现状 | 风险 |
| --- | --- | --- |
| 静态闭环稳定连续 N 次 | 未达成（缺回程） | **高**——这是全部工作的地基 |
| 传送带速度稳定、可测 | 未测 | 中——需标记物计时 |
| 物块投放位置可重复 | 未测 | 中——人工投放抖动直接吃提前量 |
| 拦截点位可达（不受死区限制） | 未验证 | **高**——受 ID2 死区约束 |

**判断**：
- 时间"够但不宽裕"。真正的风险**不是视觉**，而是机械可达性——今天 80% 的返工都来自
  ID2/ID3 的死区与过载判定，不是算法。
- **2026-10-19 21:50 修订：伪动态（传送带运行中抓住移动物块）已是 11-04 视频的硬要求**，
  不再是加分项——因为 11-04 交视频时就要求给出完整的实用价值论述。排期见
  [冲刺计划](7.sprint-plan-daily-tasks.md) 的 W3/W4：伪动态在 W3 打通、W4 录制提交，真动态留到 W5。
- 伪动态靠"传送带匀速 + 固定起点 + 光电触发固定延时 T"，不依赖视觉实时性；
  视觉在 11-04 前只需把带面映射做对、把检测画面拍出来。
- 若静态闭环在 10.23 前达不到 8/10，伪动态也会连带失守——这时退回纯静态演示，
  并在文档里明确写"动态部分 11-20 完成"。
