# 2. G2：六轴标定与低速同步写

## 目标

建立六个关节的真实标定数据，并在清空工作空间、低速条件下完成受限的六轴 `SYNC WRITE`。

## ABI 12：逐命令故障与位置结果（2026-10-08）

ABI 11 实物中 ID 2 曾被外物阻挡：WRITE 已启动并得到单播 ACK，位置只变化 9 count，最终 fault 9；障碍已移除。ACK 只证明协议应答，fault 9 表示观察期内未连续到达目标容差，并不等于通信失败。ABI 12 删除历史故障永久闭锁，下一条合法运动仍须由操作者再次显式提交；不自动重发、不自动续动。PL 在六轴广播前现场 READ 六个起点；单轴同样现场预读。输出每轴起点、目标、末次反馈、实际读数变化和目标误差。广播没有 ACK，CLI 明示 `NOT_APPLICABLE_BROADCAST`。软件 stop 若 fault 5，会指明是保持广播前的哪轴 READ，或广播后的哪轴反馈 READ，且失败不打印成功。

默认容差：六轴及单轴运动 ±30 count，标定步进 ±5 count；可在命令中调整到 `1–100 count`。默认观察期 5000 ms，可选择 1000–10000 ms（100 ms 整数倍）；仍只接受三个连续完整反馈轮次，WRITE 发前截止仍最多 2 秒。若目标与现场起点不同，即使起点在较宽容差内，也必须观察到位置读数变化才可通过；未变化则 fault 16。变了但尚未进带则 fault 9，CLI 保留部分位移数据。容差是**反馈验收阈值**，不是机械安全范围；实测闭区间和速度上限始终由 PL 检查。

原 ABI 11 标作 `home` 的六个数重新命名为**测得的参考位置**。ID 2 的 861、ID 6 的 1585 恰在下限；ID 3 的 3117、ID 4 的 2861 恰在上限。没有测得安全回位姿态，软件不自动返回这些端点，只接受操作者明确提交的六轴目标。参数和寄存器见 [ABI 12 契约](g2-abi12-registers.md)。上板验收须包含首次与重复 SYNC 的实际反馈、越限拒绝、软件停止延迟和独立断电急停，不能只凭一次“六轴都动了”标为 G2 完成。

## ABI 11 历史软件实现（2026-10-08）

用户已在安装状态下实测六轴安全闭区间和回零位置，见 [实测记录](../config/g2_measured_limits.toml)。ID 1–6 回零姿态为 `2000,861,3117,2861,2000,1585`；安全区间分别为 `1000–3000,861–1500,2000–3117,2000–2861,0–4000,1585–2500`。ID 4 的书写方向不改变数值上下限。实物观察约 1000 count 对应 90°，但未给出关节方向，不从 count 自动生成角度目标。

实际 TTL wrapper 将这些限位编入 PL，`calibrated_mask=0x3f`。`rtcs-pl-g2-six limits` 可在物理禁发时读回 PL 的逐轴 min/max/home 和原始速度上限。六轴 SYNC、单轴 move 及标定步进的目标均在 PL 发前按各轴闭区间检查；速度原始字段为 `1–1500`，示例推荐 `500`。标定步进固定 `500/10`；软件 stop 保持现场六轴位置时仍用 `1500/10`。所有数值均是协议原始字段，不推定速度或时间单位。接口和故障码见 [ABI 11 契约](g2-abi11-registers.md)。

六轴当前板端日志 `calibrated_mask=0x00 fault_latched=1` 来自 ABI 10 镜像；它没有发送 SYNC WRITE。ABI 11 上板后应先在物理禁发状态核对 ABI 与 `limits`，排查已有故障后通过 PL 复位清锁，再按实时 `inventory` 选择首次小幅同步目标。软件通过离线验证只表示可进入实物验收，不表示 G2 已整体完成。

## ABI 10 历史实现（2026-10-08）

当前单轴 `rtcs-pl-g2 move` 已扩展至 ID 1–6，接受操作者显式给出的 16 位绝对目标和协议原始速度/时间字段；PL 仍执行物理禁发、有效的最多 2 秒命令截止、一次提交一帧以及 WRITE 后 5 秒内连续三次目标 ±15 count 的反馈判定。该手动路径不受六轴校准掩码和六轴故障锁限制；`release` 仍仅限 ID 1。安装后的关节安全范围仍须实测，不能据舵机标称 4000 count 推算。

`calibrate-step` 仍由 PL 先 READ 现场起点、单次最多 ±50 count、使用原始字段 `1500/10`，但成功改为**连续三次目标 ±5 count**。ABI 10 的 PL 反馈缓冲区使 CLI 在成功和失败时都能打印每条反馈、目标差值和最终实际步差。`torque-status --id 1..6` 只读 `0x28` 的一个字节；其结果与单播协议 ACK 都不能替代位移反馈。fault 9 只表示 WRITE 起 5 秒内未完成连续三次到位确认。fault 9 后允许操作者再次显式手动标定或单轴 move；六轴 SYNC 仍由故障锁拦截至 PL 复位，`stop` 可用且不清锁。详见 [ABI 10 契约](g2-abi10-registers.md)和 [ABI 09 实物摘要](../artifacts/archive/g2-six-abi09-board-20261008/README.md)。

ABI 10 当时的六轴广播综合默认 `calibrated_mask=0x00`，所示六个数字目标会被拒绝；该状态已由 ABI 11 的实测限位构建取代。

## ABI 09 实施状态与历史操作（2026-10-06）

ABI 08 的 ID 1 成功实物记录和镜像已归档在 [ABI 08 归档](../artifacts/archive/g2-id1-abi08-20261006/README.md)：目标 2000，原始字段 `1500/10`，1.058 秒完成三次到位确认，最终反馈 2010（误差 10）；独立 READ 为 2001。原始字段不推定物理单位。用户观察的舵机中心约 2000、1000 count 约 90°和标称 4000 count 行程只记录为 ID 1 舵机信息，不作为机械关节安全限位。

ABI 09 增加 `rtcs-pl-g2-six`、PL 现场小步标定、六轴广播 `SYNC WRITE` 和逐轴反馈。寄存器与故障码见 [ABI 09 契约](g2-abi09-registers.md)。旧 `rtcs-pl-g2 move` 仍只用于 ID 1。广播帧使用 `FE 3A 83 28 08`，每个 ID 按 `ID, 0x28=1, 0x29=0, 目标2B, 原始时间2B, 原始速度2B` 组成 9 字节，再附校验和；广播无应答。PL 在发送前对六轴同一快照检查校准掩码、实测限位、物理禁发、故障闭锁和最多 2 秒有效截止时间。广播后按 ID 1–6 顺序 READ；**六轴全部在目标 ±15 count 的完整轮次连续三次**才成功，观察期从 WRITE 起算固定 5 秒。每次显式提交最多一帧广播；失败不自动重发。反馈 READ 故障给出具体 ID，后续自动六轴运动闭锁直至 PL 复位；软件 stop 仍可执行。

**ABI 09 当时综合默认 `calibrated_mask=0x00`，六轴运动在 PL 硬拒绝。** 安装后实测限位与回零姿态已在 ABI 11 录入；该段仅保留历史实施要求。`config/arm_calibration.template.toml` 是记录模板，不是限位授权。

板端顺序及命令（`/dev/uio0` 以实际 UIO 编号为准，全部由操作者执行）：

```sh
sudo rtcs-pl-g2-six --uio /dev/uio0 inventory
sudo rtcs-pl-g2-six --uio /dev/uio0 calibrate-step --id 2 --delta 20 --execute
# 观察关节方向及间隙，记录实时起点与终点；ID 3–6 逐轴重复，必要时使用 -50。
sudo rtcs-pl-g2-six --uio /dev/uio0 stop --execute
# 六轴限位经实测、重新综合且 calibrated_mask=0x3f 后，才可按实测目标写满六个 --axis：
sudo rtcs-pl-g2-six --uio /dev/uio0 move-six \
  --axis 1:目标1:1500:10 --axis 2:目标2:1500:10 --axis 3:目标3:1500:10 \
  --axis 4:目标4:1500:10 --axis 5:目标5:1500:10 --axis 6:目标6:1500:10 --execute
```

`calibrate-step` 由 PL 先 READ 指定 ID 2–6 的现场位置，再加本次有符号步差（绝对值 1–50 count），单播帧原子写 `0x28=1` 和新目标，随后三次确认；可多次显式提交，每次重新 READ，不自动重试。步差不大于 15 count 时，原位置已可能落入到位误差带，`OK` 本身不能证明发生运动，应比较 `calibrate-start`、最终反馈及关节的实际方向。`stop` 先 READ 六轴当前位置，再广播保持这些目标且保持扭矩（原始字段 1500/10），应记录从请求至实际停止的延迟。它依赖总线与舵机仍可通信，**不充当独立断电急停**；受载关节须先支撑好，再实测断电急停。若有任一 `ERR`、反馈失败、物理禁发或异常动作，停止继续提交，保存完整日志，检查负载及线缆。

G2 尚需板端六个唯一 ID 的只读记录、每轴方向/零位/实测安全界限/回零姿态、首次与重复 SYNC WRITE、越限拒绝、软件停止延迟及独立断电急停记录。只有这些齐全才将 G2 标为完成；静态抓放 100 次属于 G3。

- ABI 08 的 `g2_descriptor_guard` 曾是离线模块；ABI 09 已将其接入六轴总线路径。ID 1 单轴历史见 [ABI 08 实施记录](g2-id1-abi08-implementation.md)。
- 将实测关节 ID、方向、零位、最小/最大安全位置和回零姿态写入实际标定文件；模板 `config/arm_calibration.template.toml` 不可直接使用。
- ABI 09 以 `SIX_CMD` 为原子提交点：PS 先写六轴目标、各轴原始速度/时间和截止时间，PL 在提交边沿快照整条命令。
- 为已标定限位增加 PL 侧命令校验；无标定、越限、急停或故障时禁止发送。
- 完成 HX-30HM 目标位置、时间、速度字段与真实设备应答的核验。

## 验收证据

- 完整六轴 ID/零位/方向/限位表与回零姿态记录。
- 低速、清空工作空间下的单次与重复 `SYNC WRITE` 记录。
- 限位拒绝、软件停止和硬件急停的可重复故障测试。

## 阶段边界

当前 ABI 08 已取消 ABI 07 的起点窗、固定目标和一次性锁；本节以下关于 ABI 04–07 的文字仅记录历史实验。

ABI 04 首次 ID 1 实物试动的原 2 秒验收失败：`fault=9`、末次反馈1999；稍后 READ2006 不能倒记为准时通过。ABI 05 上板预读2006后拒绝且未发 WRITE。ABI 06 新镜像上板后 WRITE 已发出并被舵机 ACK，但 5 s 内无运动、`fault=9`、一次性锁已消耗，定因与判定方案见 [ABI 06 故障判定](g2-id1-abi06-fault9-诊断与判定方案.md)。**ABI 07 定因为 `0x28` 扭矩开关上电初值 0（卸力）**，改为把 `0x28=1` 与目标位置放进同一条原子 WRITE，并把 G1 路径收紧为结构性禁动（白名单 {PING, READ, TORQUE_OFF}，其余操作码报 `fault=13`），见 [ABI 07 实施记录](g2-id1-abi07-implementation.md)。此临时窗口不构成六轴标定，后续六轴 SYNC WRITE 仍要求每轴真实 ID、零位、方向、机械限位和急停验收。
