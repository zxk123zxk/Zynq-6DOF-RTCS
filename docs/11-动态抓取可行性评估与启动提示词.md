# 动态抓取（G5）可行性评估 + 新对话启动提示词

## 第一部分：能到什么程度（2026-10-27 评估）

### 结论

| 节点 | 能做到什么 | 把握 |
| --- | --- | --- |
| **10-31** | 传送带匀速 + 物块移动被拦中，**能演示 1–3 次成功**；写成"初步动态" | **较高（~70%）** |
| **10-31** | 稳定 ≥3/5 | 中等（~40%），报告与调试抢时间 |
| **11-04** | **≥3/5 达标**（初步动态的正式口径） | **较高（~70%）** |
| **11-04** | 8/10 | 取决于带速与 y 漂移，不强求 |

### 为什么可行（三条已成立的地基）

1. **静态闭环 13/13 已成立**，拦截点用的就是同一套姿态与七步；
2. **拦截只多一个新动作**：单轴闭爪实测 **757 ms**，其余（走到拦截点、摆好姿态）在物块到达前做完；
3. **触发链已通**：`capture_agent → 串口 → 板端 server`，Python `sleep` 抖动 1 ms 级，
   远小于 757 ms 的闭合余量。

### 唯一的硬约束：必须先限速

`T_flight = 检测线到拦截点的距离 ÷ 带速 > 3.5 s`

带长 490 mm、示教区间 295–420 mm，所以检测线可放上游 x≈120，拦截点取 x=370：

| 带速 | 距离 250 mm 的 T_flight | 判定 |
| --- | --- | --- |
| 30 mm/s | 8.3 s | ✅ 宽裕 |
| **40 mm/s** | **6.3 s** | ✅ **推荐工作点** |
| 60 mm/s | 4.2 s | ✅ 可用 |
| 80 mm/s | 3.1 s | ❌ 不够 |

**先限速，再谈算法**——这条决定成败，不是先把代码写快。
40 mm/s（4 cm/s）在视频里是清楚可见的移动，评审能看出"它在动"。

### 五个主要风险

| 风险 | 后果 | 退路 |
| --- | --- | --- |
| y 方向漂移（带面摩擦不均/投放偏） | 夹偏、夹掉 | 加挡边或导轨；或把拦截点选在带子最稳的一段 |
| 闭爪时物块已越过 | 夹空 | 缩短 T、降带速、把检测线前移 |
| 闭爪太早，物块撞到张开的爪 | 撞飞/卡住/翻倒 | 加长 T（约 50 ms 一档微调）；把等待位沿 x 后移 10 mm |
| 爪张开宽度不够物块通过 | 物块被爪挡停 | 先在静止工况量爪内宽与 40 mm 方块的余量 |
| 抬升时被带子带着走 | 拉动/掉件 | 闭爪后先原位抬 200 ms 再走 lift（复用 retreat 的垂直抬思路） |

### 三、当前状态（10-26 收盘，可直接引用）

- 静态视觉闭环 **13/13**；x 覆盖 300–403 mm、y 34.3–38.8 mm；周期 **P50 7.84 s**
- 视觉重复性 **±0.15 mm**；"稳定 0.5 s 才出点"已生效（6~7 帧）
- 夹爪：夹住堵转停 **2373–2409**，夹空合到 **2214**（差 <60 判空）
- 示教表 **6 点五轴**：295/320/345/370/395/420，**y=36 单车道**
- 单轴闭爪实测 **757 ms**；`move-six` 单步最短观察约 900 ms
- 现有命令链：`capture_agent.py --serial COM8` → `static_grasp_server.py --source stdin`
  → `g3_station_runner.py --grasp-xy X,Y --teaching-table …`

### 四、策略（沿用文档结论，不要改成"实时跟随"）

1. **提前就位**：物块到达前把臂摆到拦截点，只等"闭爪"这一下；
2. **触发时刻** = 视觉检测到物块进入上游参考线的时刻 `t0`；
3. **闭爪时刻** = `t0 + T_flight − 0.9 s`，其中 `T_flight = 实测距离 ÷ 实测带速`；
4. **限速 40 mm/s 左右**（见第一部分的表），这是先决条件；
5. 闭爪后**先原位抬 200 ms** 再走 lift，避免被带子拖走。

### 五、顺序（不要跳步）

1. 读文档 → 2. **带速实测** → 3. 按 `T_flight>3.5 s` 反推可用带速与检测线 →
4. 选拦截点（**优先用已教点，如 370**）→ 5. 确认等待位不挡带/不挡视线 →
6. 再写代码（先 dry-run 验时序，再真跑）

### 六、硬约束（都踩过，别重犯）

- `lift` 必须**六轴联动**：单轴 ID2 过竖直点（~1990 / 告警线 2020）会**静默停**报 `no_motion_ack`
- **离地之前不许横向移动**：`lift` 的 ID1 锁抓取值，横移交给 `place`
- **带件横摆必须保持高位**：`place` 先 ID1 单轴横摆，再六轴下放
- `lift`/`place` 的 **ID4/ID5 必须跟手**（`carry_wrist`），否则搬运中腕部自转把方块拧掉
- **位点数值只能来自现场 `diagnose` 实测**，不许按几何比例推算
- **禁止任何会阻止任务继续的硬门禁**，一律只告警（`CLAUDE.md`）
- **不改 PL**：触发走视觉或 PS 侧，避免升 ABI、避免重综合

### 七、验收与记录

- **≥3/5 为初步达标**，8/10 为目标；**分母含失败**，不许同位置重试顶替
- 每次记录：带速、检测线 x、拦截点 x、`T_flight`、实际偏差 mm、`grip position`、周期 ms
- 证据写 `evidence/g5-dynamic-YYYYMMDD.md`；失败也要写清失败形态（夹空前/夹空后/夹住被拖走）

### 八、第一批交付物（先给方案，不要直接写代码）

1. 带速实测的**具体做法**与预期数值范围；
2. 检测线与拦截点的**推荐取值 + 理由**（含 `T_flight` 计算）；
3. 要改哪些文件、每个文件改什么；
4. 时序预算表（从 `t0` 到闭爪的每一步耗时与抖动）。
