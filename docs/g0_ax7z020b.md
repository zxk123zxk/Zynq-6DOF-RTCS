# G0：AX7Z020B PS–PL 基础互连与 Linux 串口冒烟

G0 的范围是“板卡可启动、PS 能跑 Linux、PS 经 AXI 看见安全的 PL 外设”，不是机械臂控制。没有实物板时只能完成工程门禁，**不得**声称已经上板通过。

## 固化的硬件配置

| 项目 | G0 配置 |
| --- | --- |
| 器件 | `xc7z020clg400-2`（板卡手册标为 XC7Z020-2CLG400I） |
| PS 输入时钟 | 33.333333 MHz |
| DDR3 | 512 MiB、32 bit；Vivado 预设使用最接近的 `MT41K128M16 JT-125` |
| 调试串口 | PS UART1，MIO48 TX / MIO49 RX，CP2102，115200-8N1、无流控 |
| SD | SD0，MIO40–45，卡检测 MIO47 |
| PL 时钟 | FCLK_CLK0 = 100 MHz |
| MMIO | `0x43C0_0000`，64 KiB |

手册中的 DRAM 丝印为 `MT41K128M16TW-107`，但 Vivado 2023.2 的 PS7 预设中没有这一精确料号；脚本选用同容量/组织的 `JT-125`。取得实物后，必须按 DDR3 器件丝印、原理图及稳定性测试确认该配置，不能仅凭预设宣告 DDR 已验证。

## Vivado 2023.2

从仓库根目录执行：

```powershell
& 'D:\3.Electronic_Information\vivado\Vivado\2023.2\bin\vivado.bat' `
  -mode batch -source src/pl/vivado/create_project.tcl
```

这会生成并验证 `rtcs_system` Block Design：

```text
PS7 M_AXI_GP0 -> AXI Interconnect -> rtcs_axi_wrapper/S_AXI
FCLK_CLK0 (100 MHz) -> GP0 / interconnect / RTCS / proc_sys_reset
rtcs IRQ -> xlconcat(bit 0) -> PS7 IRQ_F2P
```

需要生成 bitstream、XSA 与报告时，在末尾加 `-tclargs build`。产物将位于 `build/hw/rtcs_system.xsa`、`timing_summary.rpt`、`utilization.rpt`。本阶段包装器没有任何外部舵机端口，`servo_tx_en` 在 `rtcs_top` 内部保持为零；不要给未验证的总线添加 XDC。

## PetaLinux 2023.2（WSL2）

在已安装且已 source PetaLinux 2023.2 环境的 WSL 终端运行：

```bash
./scripts/petalinux/create_project.sh build/hw/rtcs_system.xsa build/petalinux/rtcs-g0
./scripts/petalinux/build_sd_image.sh build/petalinux/rtcs-g0 build/sd/rtcs-g0
```

第一个脚本把 device tree 和 `rtcs-uart-smoke` recipe 同步到生成项目；不要单独复制 Peta layer 后跳过此步骤。设备树为 PL 外设保留 `generic-uio` 节点及 F2P IRQ `29`（SPI 61），当前 RTL 的 IRQ 恒低，不会产生中断。第二个脚本用 `mkimage` 从 `scripts/petalinux/boot.cmd` 生成 `boot.scr`，并导出 `BOOT.BIN`、`image.ub` 和 `SHA256SUMS` 到 FAT32 microSD 启动分区。

本机当前未安装 PetaLinux、Vitis/XSCT，且 WSL 枚举权限被拒绝；因此这里只交付了匹配 2023.2 的可执行流程，尚未产生 Linux 启动镜像。恢复当前 Windows 用户对 WSL 服务/发行版的访问并安装工具后，再执行上述命令。

## 串口冒烟验收

板卡 CP2102 枚举后将主机终端设为 **115200 baud、8 数据位、无校验、1 停止位、无硬件/软件流控**。从 SD 启动、登录 Linux 后手动运行：

```sh
rtcs-uart-smoke
```

它不会打开 `/dev/ttyPS1`，而是使用登录控制台的标准输入/输出，避免与 `getty` 争抢串口。首屏必须出现 `RTCS_G0_OK`、板卡、串口、PL 100 MHz、AXI 地址、理论串口净上限 11,520 B/s 与目标 100 行/s。每秒输出一行 `STATS`。

```text
41             -> OK 42
-2            -> OK -1
hello         -> ERR invalid_signed_32_bit_decimal
2147483647    -> ERR increment_overflow
quit          -> RTCS_UART_SMOKE_EXIT
```

连续 60 秒以 100 行/s 发送有效整数时，验收要求是应用无解析错误、无丢行，`STATS interval_hz` 不低于 100。串口的 11,520 B/s 是 115200 baud / 10 bit frame 的理论上限；实际可发送行数还取决于每行字符数、终端/USB 缓冲及调度，不能把它当作控制闭环频率。

## 串口回环验收

```sh
rtcs-uart-loopback [--device PATH] [--baud RATE]
```

必须使用**未被 `getty` 占用**的串口，否则会与登录控制台争抢。典型用法：

- 本地自回环：将目标串口的 TX、RX 物理短接，从主机端另一串口发送任意字节，应原样收回。
- 双机回环：主机串口与目标串口对接，主机发送、目标回显。

首屏输出 `RTCS_UART_LOOPBACK_OK`、设备、波特率、8N1、无流控与理论字节上限；此后每秒一行 `STATS`，报告累计收发字节数与平均速率。stdin 输入 `quit` 退出，打印 `RTCS_UART_LOOPBACK_EXIT`。

验收要求：在短接或对拷条件下，发送 N 字节后 `STATS` 的 `rx_bytes` 与 `tx_bytes` 相等且等于 N，无 `ERR` 行。波特率仅支持 termios 标准档位（9600–921600）；不支持的档位会报 `ERR unsupported_baud` 并退出。
