# V1.2 视觉与 Zynq 控制端接口联调计划

## 状态与边界

**状态：待开发。**

本阶段定义并验证视觉结果到控制端的通信契约。通信协议、传输介质和控制策略尚未确定；本计划不修改 FPGA、PS/PL、AXI、RTL 或机械臂控制代码。

## 可复用的现有视觉语义

V1.0 已提供每帧零到多个目标：

- `frame_index`；
- `timestamp_s` 与 `timestamp_kind`；
- 原图 `image_width_px`、`image_height_px`；
- `class_id`（`0=cube`、`1=cylinder`）与 `class_name`；
- `confidence`；
- 原图像素 `bbox_xyxy_px` 与 `center_px`；
- `valid`。

V1.1 完成后才可增加有真实映射依据的 Workspace 毫米坐标。当前不提供 `yaw`、Robot Base 坐标或机械臂动作。

## 联调任务

1. 共同确定传输方式、消息版本、序列化格式、更新频率和最大消息大小。
2. 明确发送零到多个目标还是由上位策略先选定一个目标；多目标选择策略不得由视觉端擅自假设。
3. 明确时钟来源、时间戳单位、跨设备时钟同步方式和最大允许数据年龄。
4. 定义空检测、低置信度、目标丢失、多目标、过期帧和标定无效的状态编码。
5. 定义像素、Workspace 与 Robot Base 三种坐标系的字段、单位、轴方向、转换责任方和标定版本。
6. 定义心跳、超时、断连、重复帧、乱序、校验失败和版本不兼容的处理方式。
7. 使用记录回放、模拟接收端和故障注入验证通信，再进入真实设备联调。
8. 保存端到端日志，使视觉帧、消息、控制决策和实际动作可以按帧编号与时间戳追溯。

## 安全语义

- 无有效目标时发送明确的空/无效状态，不沿用旧目标坐标。
- 超过约定年龄的数据必须由接收端拒绝，不能继续驱动抓取。
- 通信中断、标定无效或坐标系版本不匹配时停止产生可执行目标。
- `confidence` 是检测器评分，不等同于抓取成功概率。
- 视觉只提供观测；运动边界、关节限位、急停和执行许可由控制系统负责。

## 队友需要共同确认的问题

- PC 视觉与 Zynq PS 之间采用 TCP、UDP、串口、文件回放或其他通道？
- 消息格式、版本字段、字节序、校验与兼容策略是什么？
- 控制端需要全部检测还是单一选定目标？目标排序和类别优先级由谁负责？
- 置信度阈值、目标尺寸限制和工作区边界由视觉端还是控制端管理？
- 可接受的检测频率、最大延迟、最大数据年龄和丢帧率是多少？
- 是否要求 `yaw`；若要求，其定义、对称物体歧义和验证方法是什么？
- Workspace→Robot Base 变换由哪个模块维护，如何版本化和校验？
- 控制端如何回传接收、拒绝、执行和抓取结果？

## 计划交付物与验收

- 版本化接口规范与示例消息；
- 视觉发送端和控制模拟接收端；
- 正常、多目标、空检测、过期、断连和错误消息测试记录；
- 延迟、吞吐和连续运行报告；
- 坐标系、标定版本和失效语义核对表；
- 双方签字/确认的联调验收记录。

只有接口字段、失效处理、回放测试和真实通信联调均通过后，V1.2 才能标记完成。
