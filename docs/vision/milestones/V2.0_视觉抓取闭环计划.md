# V2.0 视觉引导机械臂抓取闭环计划

## 状态与前置条件

**状态：待开发。**

V2.0 是视觉子系统参与完整抓取闭环的规划，不表示当前已经实现。前置条件包括 V1.1 真实标定、V1.2 接口联调，以及控制团队完成机械臂坐标变换、运动学、安全边界和基础抓取能力验证。

## 目标链路

固定单摄像头采集
→ cube/cylinder 多目标检测
→ 有效性与工作区检查
→ 目标定位及必要的姿态信息
→ 目标选择
→ 控制端接收并验证时效
→ Workspace 到 Robot Base 转换
→ 机械臂规划与抓取
→ 抓取结果反馈
→ 成功结束或安全失败处理。

视觉模块仍只负责观测与定位；机器人运动、逆运动学、轨迹规划、舵机通信和 FPGA 实时控制由相应控制模块负责。

## 主要任务

1. 在最终固定摄像头与传送带条件下验证 cube/cylinder 的检测、分类、定位与连续稳定性。
2. 明确目标选择规则，包括类别、工作区、可达性、置信度、时效和多目标冲突。
3. 若抓取需要方向，单独定义并验证 `yaw`；圆柱对称性和方块旋转歧义必须显式处理。
4. 控制端对每个视觉目标进行标定版本、坐标范围、时间戳和有效性检查。
5. 建立抓取结果反馈：目标是否仍存在、夹取是否成功、是否落入指定区域。
6. 定义失败分类与恢复：检测失败、目标丢失、定位越界、不可达、通信超时、抓取失败和安全联锁触发。
7. 失败重试必须有次数、重新观测条件和安全退出；不得对过期坐标盲目重试。
8. 保存端到端证据：输入帧、检测、坐标转换、下发目标、控制状态和抓取结果。

## 计划验收指标

最终指标需由视觉与控制团队根据比赛场景共同冻结，至少应覆盖：

- cube/cylinder 分类别检测与漏检/误检；
- 像素及 Workspace 定位误差；
- 端到端延迟、目标数据年龄和连续运行稳定性；
- 多目标选择正确性；
- 空检测和目标丢失时的安全行为；
- 静态抓取成功率及失败原因分布；
- 失败重试后成功率与安全退出；
- 若进入传送带动态抓取，另行定义速度范围、预测误差和时序裕量。

G4 设计中的静态抓取成功率等数值可作为团队讨论输入，但在真实测试完成前只能标记为目标，不能写成 V2.0 已有成绩。

## 计划交付物

- 冻结的系统数据流、坐标系和接口版本；
- 最终场景检测与定位测试集及报告；
- 控制联调日志和故障注入记录；
- 静态抓取闭环演示与验收记录；
- 失败案例、恢复策略和安全检查清单；
- 如获批准，再形成动态传送带抓取的独立验收方案。

## 完成判定

只有真实固定摄像头、真实工作区、真实机械臂和完整安全链路上的抓取测试达到团队批准的指标，V2.0 才能标记完成。合成图、公开数据、离线回放或单独摄像头检测均不能替代闭环验收。
