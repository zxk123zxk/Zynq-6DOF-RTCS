# 方案对比：固定机位+平面映射 vs 模仿学习（ACT）—— 2026-10-15

**触发**：操作者发现 `resource_file/SO-ARM101.pdf` 中有"手眼标定+数据训练"教程，要求重新评估两条路线。本日结论：**维持固定机位+平面映射主线（不换）**，模仿学习列为决赛后可选分支与文档选型论证素材。

## 0. 先纠正一个概念：PDF 教的不是"手眼标定"

全文检查（两版 PDF，逐页文本提取）："手眼"二字**出现 0 次**。教程中 `handeye` 只是**夹爪相机的名字**（原文 p.36："fixed 为固定环境摄像头，handeye 为夹爪相机"），不是手眼标定。

`SO-ARM101.pdf` 实际教的是 **LeRobot 模仿学习（行为克隆）全流程**：

| 章节（62 页新版页码） | 内容 |
| --- | --- |
| 4.3 遥操作带视觉 (p.34) | 双相机（环境固定相机 + 腕相机）640×480@30fps，**主臂**拖动示教，从臂跟随 |
| 5 数据采集 (p.36) | `lerobot.record` 录 20 轮 episodes（图像+关节角），约 30–90 分钟；每轮换物体位置增加多样性 |
| 6 数据集训练 (p.39) | 云 GPU（教程用智星云 RTX4090，100k 步约 2–3 小时）或**本机训练（文档明言不推荐无独显电脑）** |
| 7 模型测试 (p.53) | `lerobot.record --policy.path=...` 加载 ACT 策略，**在 PC 上**边看相机边直接输出关节角，循环执行 |

> 两版 PDF：`docs/resource_file/SO-ARM101.pdf`（42 页，旧版）与上级目录 `SO-ARM101开源6轴机械臂使用文档.pdf`（62 页，新版，多双臂协同章节）。流程相同，本文引新版页码。

而**经典手眼标定**（AX=XB / eye-to-hand 解变换）在素材库 `graspness_/real/calibrate.py` 里，此前已评估：它依赖深度相机，我们无深度，已走平面映射替代——平面映射**本身就是**平面任务下 eye-to-hand 的正确 2D 形态。所以真正的对比不是"标定 vs 学习"，而是：

- **路线 A（我们现行）**：显式检测（YOLO）+ 显式映射（实测点对单应）+ 显式运动（示教/IK/状态机）
- **路线 B（PDF 教程）**：端到端模仿学习——示教数据训一个 ACT 网络直接从图像出关节角，**检测、映射、运动学全部隐式学出来**

## 1. 逐维度对比

| 维度 | 路线 A：固定机位+平面映射 | 路线 B：模仿学习（ACT） |
| --- | --- | --- |
| 已有资产 | **YOLO V1.0 已交付且两种背景可用**；G3 状态机/PL 安全逻辑就绪；只差 ROI+映射（G4 步骤 3，约 1 天） | **从零开始**：无主臂、无 episodes、未训过模型 |
| 硬件门槛 | 现有全部够用 | 需**主臂**（HX-10HM 遥操作臂，我们没有）或改用键盘遥操作；训练需云 GPU 租用（RTX4090 级，2–3h/次） |
| 与我们控制架构的兼容 | 视觉输出 `(x,y)` 给板端，一次映射一次到位，与"单帧提交"命令模型天然匹配 | lerobot 原生是 **PC 直驱舵机**（COM 口+驱动板），链路里没有 FPGA；搬到我们架构需自写 lerobot 机器人类对接 Zynq，且 PL 需从单帧命令改成 30–50 Hz 关节目标流——**会动我们最核心的 PL 设计** |
| 到 11.04（20 天）的确定性 | G3 今天示教→W2 盲抓→W3 视觉接入，路径在冲刺表内 | 采集+训练+联调，任何一环翻车都没有兜底；教程自己也要求"训练与推理场景保持一致" |
| 可验收性 | 映射误差（mm）、成功率 X/10、单次耗时——**全部可测可复现** | 成功率是统计性的；失败无法归因（看错了？动手错了？）；误差无毫米口径 |
| 现场鲁棒性 | 场景已锁死（两种背景+ROI+白纸包裹），可解释可控 | 教程原文（p.53）："推理前应确认模型、摄像头配置和现场摆放与采集训练时保持一致；**其中任一项发生变化，都可能导致动作效果下降**"——比赛现场恰是变量最多的地方 |
| G5 动态拦截（11.20 决赛） | 匀速预测+拦截是经典解析问题 | 运动传送带上的时序抓取需在数据里覆盖且学得会，难度显著更高 |
| "AI 含量"故事 | 中：检测是 AI，映射是几何 | 高：端到端具身智能，对"具身智能赛道"评委更有话题性 |

**路线 B 真正的代价清单**（不换的具体理由）：买/组主臂或写遥操作桥 → 录 20+ 轮合格 episodes → 租云 GPU 训练 → 自写 lerobot↔Zynq 机器人类 → 改 PL 支持连续流 → 现场一致性调参。每一步都吃天数，且**会废弃已经能用的 YOLO 检测器**。20 天硬节点下没有容错空间。

## 2. 问题一：模仿学习路线是怎么"识别物品"的

**没有显式识别。** 教程原文（p.53）："模型会融合环境信息（主要是视觉观察）和自然语言指令，并将其**直接映射为控制机器人的具体动作**……基于'行为克隆'的模仿学习……**端到端推理能力**。"

具体机制：双相机原始帧 → CNN 编码器（ACT 用 ResNet18 级别骨干）提特征 → Transformer 预测**未来一段关节角序列**（action chunk）→ 逐周期发给从臂。网络内部从未出现"类别、检测框、像素中心、毫米坐标、逆运动学"任何一项——"看到什么"和"怎么动手"被压成一个黑盒映射，全靠示教数据里学。

推论：
- 数据里没见过的样子（光照、摆放分布、背景）就可能失效，且**无法定位失败原因**；
- 物体外观/场景若变（比如喷漆后的方块、决赛新桌面），要么重采重训，要么赌泛化；
- 我们赛道场景（两种固定背景、固定工件、平面抓取）恰恰是**结构化最强**的一类——用显式几何做是最省的，学习是杀鸡用牛刀且刀还没磨好。

## 3. 问题二：训练好后还需要 FPGA 实时运算吗

分三层回答：

1. **训练产出不是查找表，是活网络。** 训练得到的是几十 MB 的神经网络权重；推理时**每个控制周期（相机 30fps、控制 30–50 Hz）都要对当前图像跑一次网络前向**。所以"实时运算"永远存在——问题是**在哪算**。
2. **教程的原生答案：全部在 PC 算，FPGA 不在链路里。** lerobot 的推理循环跑在 PC（PyTorch/conda 环境），PC 通过自家驱动板直接驱动从臂。整条流水线没有 FPGA。
3. **对我们的架构**：若走路线 B，算力仍在 PC；Zynq 退化为"接收关节目标流的执行器"。按赛道规则（选题指南 3.2.2.3，"AI PC 职责"明确列有**"策略模型运行"**，FPGA 职责是"实时处理、运动控制、安全逻辑"）——**架构上仍然合规**，两条路线都不违规；差异在工程与故事。而想把 ACT 搬上板做"本地智能体"卖点：Zynq-7020 双 Cortex-A9 跑 PyTorch 不可行，Vitis-AI DPU 量化自定义 Transformer 策略 3 周内做不完——**做不了**。

反观路线 A：重的是 YOLO（留在 PC，规则允许且 G4 已写明兜底），轻的是**单应矩阵乘、ROI 裁剪、坐标变换**——这些恰是能真实放进 PS/PL 的计算，强化"FPGA 是核心而非转接板"的评审故事（赛道原文红线：FPGA 不得只用作 USB/串口/GPIO 转接板）。

## 4. 结论与建议

1. **主线不换：固定机位 + YOLO + 平面映射。** 决定性理由是 20 天硬节点、已有可用资产、可验收口径、与现架构零冲突，以及 G5 的可解性。
2. **模仿学习的两个保留用法**：
   - **文档选型论证**：作品文档写一节"技术路线对比"（本页可直接引用），说明为何在固定工位任务选显式几何——有理有据的选型本身就是加分项；
   - **决赛后/时间富余的实验分支**：若 11.04 提前交付且设备到位（主臂、云 GPU），可作为演示"可扩展到端到端学习"的彩蛋，不进主线、不占关键路径。
3. **不新增任何验收仪式**：本对比不产生新的测试义务；G4 步骤 3（平面映射）仍按 1 天口径推进。
