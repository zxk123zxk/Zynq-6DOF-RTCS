## ABI 06 上板 `fault=9` / 舵机无运动：定因分析

- 现象：ABI `0x52540006` 一次性试动，预读 `2005`、提交通过、`sample=1..99` 全部 `position_raw=2005 servo_error=0`、`ERR g2_fault=9 write_sent=1`；舵机 5 s 内无可见运动。
- 已确证（可引用）：`g2_fault=9` 是“WRITE 已启动但 5 s 观察期内未形成三次连续 1998±5”的判定；`write_sent=1` 表示一次性锁已消耗，只有 PL 复位可再提交。
- 已确证：WRITE 确实上总线并被舵机 ACK（`g1_fault_code==0` 是进入反馈阶段的唯一路径，而 WRITE 的 fault 0 只能来自“6 字节应答 + 校验通过 + ERROR=0”）；实际帧 `FF FF 01 09 03 2A CE 07 00 00 32 00 C1` 与幻尔官方 SDK `move_to(1998, speed=50, time_ms=0)` 逐字节一致。→ 接线方向、1 Mbps 8N1、ABI、帧编码、发前门禁均已证明正确。
- 未定项：舵机执行条件（0x21 模式 / 0x13 或 0x10 最大扭矩 / 0x28 扭矩开关 / 0x1B-0x1C 死区）或电气（供电需 9–12.6 V、堵转 3 A）、机械（顶死/限位）。当前镜像无观测手段（PL 只读 0x38 两字节），这是结构性缺口。
- 新发现：`docs/resource_file/HX-30HM寄存器列表及参数.xls`（工厂）与官方 SDK 寄存器表在 0x28/0x29/0x2C/0x13 上冲突；官方 `move_to()` 与 NexArm 例程均无扭矩/模式使能步骤。需只读回读定案。
- 产出：新增 `docs/g2-id1-abi06-fault9-诊断与判定方案.md`（日志解码、证据链、判定读表与判定树、零改动判定步骤、M1–M6 修改方案、构建门槛、待确认信息）；并同步更新 `docs/0.1hardware_bringup.md`、`docs/1.G1-single-servo-protocol.md`、`docs/2.G2-six-axis-calibration.md`、`docs/SD启动与项目迭代操作说明.md` 的 ABI 06 证据记录。

## ABI 07 迁移（力矩开关修正）与 SD 构建解阻

- 定案：`0x28` 扭矩开关（SRAM，上电初值 0 = 卸力）是 ABI 06 `fault=9` 的根因；用户把舵机总线拔掉后可自由转动，反证电气/机械无问题。`0x28` 写 128 会把当前位置标定为 2048，本路径只用 1/0。
- RTL：新增 `OP_TORQUE_MOVE`（`0x28..0x2F` 8 字节块、15 字节帧、`LEN=0x0b`）与 `OP_TORQUE_OFF`（8 字节、`LEN=4`）；**删除**只写 `0x2A` 的位置专用帧；`rtcs_top` 加 `g1_path_allowed()` 白名单 {PING, READ, TORQUE_OFF}，其余操作码报 `fault=13` 且不发字节。`hx30hm_g1_engine` tx 复用按 opcode 展开、长度查表。
