## 相机/场景选型决策（白方块、ROI、换不换相机）

操作者提出：白方块用白喷漆解决；反对用 ROI（怕比赛现场场景不同导致演示失败）；
担心"摄像头无纵深、只能识别色块，稍有干扰就出意外"；问要不要换摄像头、京东买什么。

产出 `docs/vision/相机与场景选型决策-20261014.md`，结论：

- **白方块**：可做，但三条不能省——必须**哑光**（亮面高光会把 YOLO 像素中心拉偏，映射用的是像素中心）；
  白 + 浅木桌面 = 低对比，而模型卡明确记录"低对比白色 cube 漏检"，故桌面需铺深色哑光垫或保留黑方块；
  **必须重跑点检**。另建议做白 + 高饱和两色，用数据选。喷漆会改摩擦 → G3 `grasp` 接触 count 要重测。
- **ROI：顾虑指错对象**。方案前提本就是场景固定；任何让 ROI 失效的变化同时会让**平面映射**失效，
  而映射必须在现场重做，所以 ROI 不引入新的脆弱性；ROI 是配置不是代码，现场 1 分钟改。
  改进：**ROI 由物理工作区反推**（映射给出对应像素区域的外接矩形），不要手画像素框。
- **纵深问题**：单目无深度属实，但"只能识别色块"不准确（YOLO 也用形状/纹理，证据是木纹被误判）。
  平面假设下高度是**示教常量而非测量量**，所以够用。"干扰就出意外"的解法是
  场景固定 + 越界/歧义拒绝 + 放弃本次抓取 + 降级路径，**不是换摄像头**。
- **要不要换**：值得换，但理由不是深度，而是 **FOV 120°→60~90°**（现在工作平面只占中央 60%，
  等于浪费大半传感器；缩 FOV 可让工作平面像素数翻 2–4 倍并大幅减畸变）+ 1080p + **必须手动对焦/定焦**
  （避开 AF）+ UVC 可锁曝光；全局快门为 G5 可选。
  **不买深度相机**：D435i 最小测距约 28 cm（可能比抓取距离还近）、RGB 是 30fps 卷帘、
  Windows 需 SDK、ARM 难跑、价格千元级。
- **京东检索价（2026-10-14，波动需复核）**：中维奥柯 UVC 工业模组 ¥128–¥350（选"无畸变"镜头版本，
  避开 160°/180° 鱼眼）；DECXIN/ELP AR0234 全局快门 1080p@120fps ¥230–¥700；
  RealSense D435i ¥1500–¥3700（不建议）。
- **决策建议**：不停主线（白方块+ROI+重跑点检明天就可做），同时下单一台
  「200万 1080P USB3.0 + 无畸变 ~90° + 手动对焦 + 可锁曝光」；到货后 A/B 对比
  `detection_audit` 合规率与平面映射 `validate max_mm`，用数据决定切换。
  **要换就现在换**（平面映射还没动工，切换成本最低）。
- **另一条可能更管用的路**：换相机前先花 1 小时把 `--mode opencv`（背景差分+形状）与 YOLO
  在同一素材上比一次；固定背景+已知形状下传统 CV 往往更稳且无类别混淆。

## 晚间追加：根因判定、补光优先、喷哪个、四角标记定位

操作者新观察：绿带识别失败主因是**背景与物体都过深**；**摄像头高悬向下 + 带上垫白纸后识别很清楚**；
工位打光是"在摄像头眼中很昏暗"。已决定在纸上做标记贴传动带四角作定位坐标。
绿带点检认为已无意义。

补充结论（写入 `docs/vision/相机与场景选型决策-20261014.md` §6）：

- **先补光，可能不用喷漆**。物理上：低照度时黑方块与深绿带一起被压进噪声底；照度上去后绿带
  （中等反射率）亮度抬升而黑方块仍低 → **亮度差被拉开**。顺序：加灯 + 固定灯位 → **重新锁定曝光**
  （加灯后必锁，昏暗下自动曝光会拉长曝光造成运动模糊）→ 重拍验证。
- **喷方块，不要喷传送带**：皮带运行中反复弯折，**漆层会开裂脱落**，碎屑污染工件与画面；且不可逆。
  优先级：补光 → 垫白纸（仅 G4 静态，皮带一动纸会被带走）→ 喷方块 → 换白皮带 → 喷皮带（避免）。
- **"高悬向下"的代价是像素尺度下降**（架得高覆盖大但每毫米像素数少）。**已在
  `plane_mapping` 增加像素尺度指标**：`local_scale_mm_per_px`（映射雅可比的几何平均 sqrt|det J|，
  有限差分实现，两种方法通用）+ `pixel_scale_report`，`calibrate` 会打印
  `pixel scale X.XX px/mm` 并在低于 `ENOUGH_PX_PER_MM=2.0` 时告警。今晚可手测粗值：
  白纸上量 100 mm 数像素数。按 640×480+120° 估算工作区 400mm 宽约占 380px → **~0.95 px/mm**；
  换 90° FOV(~1.7×)+1080p(~1.9×) → **~3 px/mm**，这是换相机最硬的量化理由。
- **四角标记的正确定位 = "相机是否被碰动的复位检查"，不是标定点**：4 点恰是单应最小配置，
  必然过拟合、残差恒 0、无法自检；且若标记像素由另一套方法读出，就引入了第二套误差源。
  标定点仍须用**工件本身**放到已知毫米坐标、用要用的那个 YOLO 读中心（`plane_mapping collect`），
  ≥6 点求解 + ≥3 独立验证点。

**代码**：`src/vision/plane_mapping.py` 新增 `local_scale_mm_per_px` / `pixel_scale_report`，
`_print_report` 增加 pixel scale 行与不足告警；**新增 5 项测试**（已知尺度、放大后不足、
poly2 各向同性、无点对时返回无效而非 0），视觉单测 **85 → 90，全绿**。
同步三处测试数（README / 验收细则 / REPRODUCTION_GUIDE_ZH）85 → 90。
**未做**：绿带点检（操作者判定无意义，未跑，如实记入）。
