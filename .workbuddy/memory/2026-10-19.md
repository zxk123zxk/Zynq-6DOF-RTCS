## 21:10 夹紧过载拖死 move-six 的机理（用户问：硬件还是脚本）

- **不是脚本问题，是 PL 故障策略 + 舵机堵转**：
  1. 命令 ID6=2200，物块在 ~2377 挡住 → 电机堵转、电流升高 → 舵机 ERROR bit5(过载 0x20) 置位；
  2. 该 ERROR 出现在**每一次状态回包**里，只要持续夹着，ID6 每个读回都是 0x20；
  3. PL 的 `move-six` 规则是"任一轴回包 ERROR 非零 → engine_fault=8 → 整条 fault=5"，
     不区分"夹爪正常堵转"；于是 lift/place/exit 全部被 ID6 的过载拖死。
- 为什么"夹住即悬空"也会过载：命令 2200 远低于接触位 2377，爪子在物块上一直推，不是在"刚好夹住"。
- PS 侧可行：闭合目标取接触位附近（如 2370），轻微接触不触发堵转；或降 ID6 扭矩上限。
- PL 侧可行（需重综合，明天再说）：给 move-six 加"忽略指定轴 ERROR"掩码，或加独立 grip 保持命令。
- 尚存疑点：用户称脚本是新版，但新脚本 + `expect_overload=true` 应判 `CONTACT` 而非 FAIL；
  已在板上给自检命令（打印 plan 的 gripper 字典 + 用样例输出跑 judge_gripper）定位。
